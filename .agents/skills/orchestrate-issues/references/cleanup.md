# Cleanup as the run goes

Clean up after each `confirmed` merge, and after a ticket is released or withdrawn, rather than at the end of the run. Start only once the ticket's writer is released and every reviewer process on its PR has exited. This cleanup is the run's own work and needs no approval from the maintainer: everything it removes was made by the run's writers, filers and reviewers for a ticket that is finished.

1. Run the [clean-worktrees](../../clean-worktrees/SKILL.md) dry run from the main checkout. Inspect the rows for the ticket's worktree, its local branch, its web editor driver directory, its `pr-<N>` review job directory and the run's finished scratch directories, then apply it.
2. Run `clean-artifacts --ticket N` (with `--record`, `--coordinator` and `--expect-revision` like every record change). It removes each `writer-N-*`, `launch-N-*` and `resume-N-*` directory under the artifact parents the ticket's writers were given, the private evidence a writer keeps there (rendered assets, copied installs, before-and-after images, snapshots) and the launch streams, once the ticket has no writer or pending start and no process names the directory, unlinking links without following them, and records what it removed and what it kept. The writer's report is on the PR and the ticket; nothing in those directories is needed after the merge.
3. Clear the other worktrees the run made for the ticket and no longer needs, such as a reproduction, a probe or a replaced attempt, through clean-worktrees' `--remove <absolute-directory>`; the next apply deletes its local branch once every commit on it is on origin/main or a merged pull request carried its tip. A branch holding work no PR carries stays and is named in the report.
4. Record each clean-worktrees removal with `disk-recovery --removed <path> --branch <branch> --classifier "<its row or the command that removed it>"`; `clean-artifacts` records its own.

A worktree or branch a guard keeps (uncommitted or unpushed work, a live process, an unmerged commit) stays, with its reason in the report; never force it or delete with `-D`. Never touch a worktree or branch the run did not create, or one another ticket's writer still uses.
