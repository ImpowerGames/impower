# Locations beside the worktrees

What clean-worktrees lists after the worktrees, and when each goes.

## Web editor driver directories

The web editor driver keeps a directory per checkout under `%LOCALAPPDATA%\impower-driver` (the machine's temp directory elsewhere, never a checkout's `.tmp/`; `IMPOWER_DRIVER_HOME` overrides it), named by a hash of the checkout path, with a `checkout.json` owner record naming the absolute checkout path it hashed and each session's server record and browser profile inside. The run lists the directory of every worktree it removes, with its size, and removes it under apply unless a session in it has a server record naming a live pid, a profile claim under 30 minutes old, or a claim lock under 30 seconds old, a running process's command line names the directory, or anything in it that the decision reads (its entries, a record, a claim) cannot be read or is a link. A directory that matches no worktree goes under the same rules once the checkout its owner record names no longer exists, however that checkout was removed, and so does one that matches no worktree and holds no owner record: every driver launch writes the record, so such a directory has had no launch since records began, and the browser profile it holds is a cache the driver rebuilds. One whose recorded checkout is still there, or whose record is unreadable or not a plain file, is listed with its size and retained. Directories of retained worktrees are not listed.

## Review job directories

The same run lists every directory under `<main checkout>.review-jobs`, the root that holds review plans, journals, diffs and reviewer probe checkouts. The review launcher removes a reviewer's probe clones and installs as soon as that reviewer exits, and the adjudicating writer runs the same removal from the journal, so while a PR is open its directory holds the plans, journals and reports the review checkpoint and the merge gate read, plus whatever a failed probe cleanup left. A `pr-<N>` directory is removable when GitHub reports PR (or issue) N closed (a merged PR is closed; the lookup is one `gh api repos/{owner}/{repo}/issues/N` REST call, since `gh pr view` reads through GraphQL, which a cloud container's network policy can block, and a lookup that fails keeps the directory), every launcher `*.jsonl` journal in it reads in full, no process a journal records is running, no process command line names it, and no embedded repository has a dependant outside the directory ([ownership protection](classification.md#review-job-ownership)). A `test-*` directory is a standalone check's scratch folder kept outside TEMP (the cross-provider continuation test's, for one); it is removable under the same process and repository rules, with no GitHub lookup, and retained when it holds no journal naming its process. Anything else under the root is retained with its reason. Removal unlinks every symlink and junction inside the directory before deleting it and never follows one, since probe checkouts hold `node_modules` junctions into live worktrees. A recorded process counts as running only while the process now holding its pid started when the journal says it did, so a pid Windows has since handed to an unrelated program does not retain the directory; a pid recorded without a start time, or whose start time cannot be read, still counts by its number.

## Filer job directories

The same run lists every directory under `<main checkout>.filer-jobs`, where `scripts/filer-worktree.mjs` keeps each filing run's `owner.json`, the filer's repro files and, under `leftovers/`, a patch of whatever uncommitted changes the filer left in its tree when the helper removed it, each row with its size. One is removable when its `owner.json` reports that the run removed its tree, or names a tree that is gone and is no registered worktree; no process its `owner.json.lock` names is running; no process command line names it; and it holds no registered worktree or embedded repository. One without a readable `owner.json` is retained for a person. `--apply` removes the removable ones the way it removes a review job directory, unlinking links first, and records them in the log.

## Scratch directories

The same run lists two scratch locations the regression workflow writes, each row with its size, and `--apply` removes the removable ones and records them in the log. A `redgreen-*` directory under the main checkout's `.tmp/` holds a red/green run's snapshot and its `red.log` and `green.log`; it is removable once it was last written more than a day ago and the pid its `owner.json` names, the red/green run that made it, is not running. A run under the main checkout's `.git/test-suites/` is removable when its `run.json` reports the coordinator released it or names a coordinator pid that is dead, and no unfinished attempt's child pid is running; a missing or unreadable `run.json` keeps it, since a run may be starting. For both, a process whose command line names the directory, or a process listing that failed, keeps it. A linked worktree's test-suite runs live in its own git dir and go with the worktree.

## Writer artifact directories

A resolve-issue writer allocates its private artifact directory, `writer-<N>-<suffix>` with an `owner.json` naming the issue, the writer, its session and its worktree, under the scratch parent its brief names (`.agents/skills/resolve-issue/writer-artifacts.mjs`), which is the session's private scratch directory under the system temp directory, in the layout the runner notes give, or a directory one level below it (an orchestrate-issues run's artifact parent). What a writer keeps there (rendered assets, copied installs, snapshots) is the bulk of a run's scratch, and an orchestrate-issues coordinator removes a finished ticket's with `clean-artifacts`. The same run lists every such directory under the main checkout's session scratch directories, with its size, and under `--apply` removes one once the worktree its `owner.json` names no longer exists, or that worktree is still there (the allocator records the directory it ran from, often the main checkout) but the issue it names is closed on the tickets repository (`gh api repos/<tickets repo>/issues/N`, one REST call per issue), and no process names the directory; one whose worktree stands on an open issue or one whose state cannot be read, whose record cannot be read, or that names no absolute worktree or issue stays with its reason.

A worktree's other scratch goes with it too. `scripts/test-suite.mjs`, `scripts/check-agent-tooling.mjs` and the standalone checks it runs, the drive-vscode-web driver, the review launcher `scripts/agent-handoff.mjs` and `scripts/filer-worktree.mjs` point `TEMP`, `TMP` and `TMPDIR` for themselves and every child at the ignored `.tmp/` at the root of their own checkout (`.agents/skills/drive-web-editor/worktree-temp.mjs`), and a red/green run keeps its snapshot and gives its test command the same directory. A removal row lists `.tmp/` among the ignored paths it takes, and nothing under the system temp directory needs a sweep for worktree runs.
