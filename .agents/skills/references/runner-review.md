# Reviewer execution mappings

For originating-task capability evidence, see [continuation conformance](runner-continuation.md). The opt-in [supervised review route](review-supervisor.md) selects the registered Windows Codex app or Claude CLI adapter; unsupported configurations retain the awaited mode below.

## Headless serial sessions

The caller supplies exact models, executable paths and argument arrays. Inspect the installed CLI help before launch; available options and served models can differ by installation.

### Claude review agents

For the opt-in supervised route, set each review entry's `transport` to `native-claude-json`, use the native executable with `--output-format json`, and retain it until actual process exit. The supervisor checks native terminal success in addition to completion artifacts and published reports. Other unsupported reviewer transports retain awaited mode until their native outcome mapping is implemented and verified.

For Claude Code, the installed reviewer definition can be invoked as:

```text
claude -p --agent reviewer-opus-5-5 --allowedTools "Read,Grep,Glob,Bash,Write" "<filled reviewer prompt>"
```

Use `--output-format json` when collecting a machine-readable session ID and result. The minimal definitions under `.claude/agents/` are generated from `.claude/reviewer-models.json` by `node scripts/generate-reviewer-agents.mjs`; `--check` checks their content, refuses unregistered reviewer definitions and validates `.claude/reviewer-defaults.json`. The caller selects a definition or leaves the launcher to resolve one from that defaults file, as described in [default reviewer routes](runner-reviewer-defaults.md); shared skills contain no model-selection table.

### Codex review agents

Codex review steps default to the full-access route below, which gives a Codex reviewer the same reach as a Claude reviewer's Bash and Write: it runs as the user, clones the reviewed head into its private directory, installs dependencies there and runs tests, including probes it writes, through `node scripts/test-suite.mjs run` with the machine-wide reservation. The launcher adds these instructions to its prompt. Its guardrail is the repository's shared hook policy (`.agents/hooks/policy.mjs`): typed issue creation, shared stash mutation, local test runs wider than the named files, generated-file edits and the write hazards (control bytes, .NET relative paths). Project hooks cannot apply, because the reviewer's working directory lies outside every checkout and `--ignore-rules` drops project rules, so the launcher writes a `hooks.json` into the reviewer's fresh `CODEX_HOME`, which Codex loads despite `--ignore-user-config`. The hook runs the shared entry point of the checkout running the launcher (the reviewed head when the launcher runs from the reviewed worktree, which already supplies the launcher code itself) by the launcher's absolute Node path; any failure of the hook command exits 2, because Codex lets a tool call through when a hook fails any other way. Claude's doubled-backslash hook does not apply: it guards the Claude shell tool, which can collapse doubled backslashes before the shell runs, and Codex passes its command text to the shell unchanged. Claude's PowerShell `jq`-quote check does not apply either, because Codex's one shell tool does not name its shell ([runner maintenance](runner-maintenance.md)). Both routes keep the isolated `CODEX_HOME` and the in-memory `GH_TOKEN` report delegation described below. These hooks are static guardrails, not a containment boundary.

The sandboxed route remains an explicit opt-in for a review that needs no execution. Its elevated Windows sandbox denies the `Win32_Process` census and writes to the machine-wide Vitest reservation store; esbuild can also fail while walking parent directories. For a sandboxed reviewer, use the [scoped execution service](../review-pr/HANDOFF.md#delegated-tests-and-benchmarks) for caller-approved test files, fixture benchmarks and [bounded editor attempts](../review-pr/references/editor-delegation.md). An editor grant lets the Codex reviewer author script text and UI requests, inspect the driver's transcript and view PNG copies saved in its private directory. The coordinator starts and stops the supported editor/player driver in a separate session and runs the real process census; delegated Vitest still takes its machine-wide reservation. These operations run in the coordinator's environment, outside the reviewer sandbox, while the reviewer requests and inspects the results. This does not grant the reviewer filesystem access or make direct sandbox execution supported. Without a delegated operation, a sandboxed reviewer discloses the gap, and a review that requires that execution uses the full-access route; never substitute an empty process census or an unlocked test run. A full-access reviewer may still be granted the service when the coordinator wants a fixed test or benchmark run in its own environment, or a coordinator-owned editor session (see [editor delegation](../review-pr/references/editor-delegation.md)).

For Codex CLI, a separate serial review session can be launched with `codex exec -m <caller-model> -C <absolute-worktree> --json -o <private-final-file> -`, supplying the filled prompt on stdin. Select permissions appropriate to the authorized review and its private artifacts. When launched through the handoff launcher, Codex review routes receive delegated in-memory GitHub report access and are expected to post their own report; a reviewer without posting capability returns the full report to its caller, which posts it verbatim and reads it back. Do not remove restrictions to hide a denied operation.

The `native-codex-jsonl` implementation accepts two exact grammars, told apart by `--sandbox`. The default full-access grammar requires Windows executable version `0.159.0` or a later release (`minimumFullAccessCodexVersion`), the build on which `CODEX_HOME/hooks.json` was observed to load under `--ignore-user-config`: `exec --model <caller-model> -c 'model_reasoning_effort="<caller-effort>"' -c 'approval_policy="never"' --sandbox danger-full-access -c 'model_provider="openai"' --cd <private-review-directory> --skip-git-repo-check --ignore-user-config --ignore-rules --strict-config --json --disable multi_agent --disable multi_agent_v2 --dangerously-bypass-hook-trust --output-last-message <fresh-private-report> -`. Declare its `permissions` as `{ "sandbox": "danger-full-access", "approvalPolicy": "never", "networkAccess": true, "cwd": "<private-review-directory>", "artifactWrites": "handoff-directory", "codexHome": "<absolute-existing-Codex-home-holding-auth.json>" }`. `--dangerously-bypass-hook-trust` runs the hooks the launcher installed without persisted trust, which a fresh home never has; the sandbox configuration keys and the `windowsSandbox` and `sandboxStateHome` fields are refused on this grammar, since they would have no effect. The launcher copies only `auth.json` from `codexHome` into the fresh owner-protected home, adds `hooks.json`, and runs no sandbox provisioning check. The rules below on model and effort insertion, refusal listing, private directories, report paths and the completion directory apply to both grammars; the TEMP restriction and the provisioning check belong to the sandboxed grammar only.

The opt-in sandboxed grammar requires Windows executable version `0.154.0` or a later release (`minimumCodexVersion` in `scripts/reviewer-security.mjs`, checked against both `--version` and `doctor --json`; prereleases are refused). Its argument grammar is `exec --model <caller-model> -c 'model_reasoning_effort="<caller-effort>"' -c 'approval_policy="never"' --sandbox workspace-write -c 'windows.sandbox="elevated"' -c sandbox_workspace_write.network_access=true -c 'model_provider="openai"' -c 'sandbox_workspace_write.writable_roots=[]' -c sandbox_workspace_write.exclude_tmpdir_env_var=true -c sandbox_workspace_write.exclude_slash_tmp=true --cd <private-review-directory> --skip-git-repo-check --ignore-user-config --ignore-rules --strict-config --json --disable multi_agent --disable multi_agent_v2 --output-last-message <fresh-private-report> -`. These are argument-array entries, not shell interpolation. Every entry is mandatory and verbatim except the per-reviewer `--cd` and `--output-last-message` paths. A step whose reviewer is resolved from the defaults omits `--model`, `model_reasoning_effort` and the step `effort`, and the launcher inserts them; a step with an explicit `reviewer` carries all three, with `effort` equal to the `model_reasoning_effort` value. The launcher checks the whole array and the step's `permissions` before reserving a slot, and one refusal lists every missing or mismatched entry. Declare `permissions` as `{ "sandbox": "workspace-write", "approvalPolicy": "never", "networkAccess": true, "cwd": "<private-review-directory>", "artifactWrites": "handoff-directory", "windowsSandbox": "elevated", "sandboxStateHome": "<absolute-existing-authorized-Codex-home>" }`; use only when private artifacts and GitHub report posting are authorized. The job directory must be outside TEMP so Codex can create its helper aliases. Each independent reviewer needs a disjoint private directory (its REVDIR under the round's job directory) and fresh report path, excluding repository and supervisor state. The launcher adds only a fresh completion directory with `--add-dir`, separated from protected native stdout/stderr evidence. Alternate roots, profiles, config overrides and bypasses other than the full-access grammar's hook-trust flag fail before launch.

Reviewer processes receive no originating host session credentials/routing. The isolated Codex environment also removes every case-insensitive OPENAI_ variable, including ambient account credentials and endpoints, before setting its explicit route. The Codex reviewer receives a fresh owner-protected `CODEX_HOME` outside TEMP. It copies only authorized `auth.json`, `.sandbox/setup_marker.json` and `.sandbox-secrets/sandbox_users.json` from the explicitly declared existing setup home as opaque bytes, without inherited configuration, rules, plugins or endpoint overrides. The native `doctor --json` must report complete elevated provisioning before reviewer execution; missing or unverified setup refuses launch and never invokes provisioning. These copied setup files do not define the reviewer write scope: explicit launch permissions do. Native process stdout/stderr and actual launch arguments remain coordinator evidence; completion JSON is reviewer-authored. The coordinated live acceptance must verify actual `exec` sandbox enforcement, ordinary Git/report access and private-home compatibility. The explicit elevated backend is required because without it an actual exec selects read-only despite workspace-write arguments. On the minimum build, an actual Sol high exec through the launcher with this grammar, the protected existing-state copy and delegated GitHub access read a public repository file, ran `git status` and `git rev-parse` on the reviewed checkout, wrote in its private directory and ran `gh api user`, while an owner-only file read and a repository write were denied ([probe record](https://github.com/ImpowerGames/impower/issues/621#issuecomment-5704126132)). This is evidence for that build, not portable sandbox support. Later releases are admitted on the doctor provisioning check alone; when a later build misbehaves under the sandbox, repeat that probe on it and raise the minimum or record the regression. The integrated native launch and reverse private-artifact workflow were subsequently verified at `a49bedb`: [artifact report](https://github.com/impowergames/impower/pull/561#issuecomment-5674233467) and [acceptance evidence](https://github.com/impowergames/impower/pull/561#issuecomment-5674331262). That no-findings loop demonstrated return, original-writer claim, finalization and later steering; it did not demonstrate an actual correction or provide independent production readiness credit.

After stripping inherited Git overrides, the launcher sets only one trusted `safe.directory` value to the exact canonical forward-slash reviewed checkout and disables optional index locks. The same normalized environment passed both direct native sandbox and actual integrated model-exec Git checks, followed by the private-artifact reviewer workflow at `a49bedb`. No wildcard or global Git setting is added.

The reviewer reads the frozen repository by absolute path, loads its supplied review instructions, posts the full report, and writes the guarded completion artifact. JSONL stdout and stderr are separate. Success requires native `turn.completed` and a complete assistant response, actual process exit, and the existing posted-report checks. Missing completion, errors, failed turns, duplicate terminal events and truncated output cannot pass. Interruption can end without a terminal JSONL event; absence alone does not prove cancellation. This automatic route does not use the awaited mode's caller-posting fallback.

Both native collaboration feature flags must be explicitly disabled with `--disable multi_agent --disable multi_agent_v2`. Missing, duplicate or overriding feature arguments fail preflight, preserving the launcher's reviewer reservation ownership even when inherited settings enable collaboration.

## Register the originating Claude CLI

Before starting the intended writer, create a private directory outside the writer/reviewed checkout and Git administrative directories, plus a private JSON hook configuration with `directory` and the absolute native Claude `executable`. Add session-local command hooks for `SessionStart`, `UserPromptSubmit`, `MessageDisplay`, `Stop` and `SessionEnd`, plus `PreToolUse`, `PostToolUse` and `PostToolUseFailure` with matcher `Bash`, each invoking `node <absolute-repo>/scripts/claude-continuation-hook.mjs <private-hook-config.json>`. Preserve the writer's chosen tools, model, effort and permissions; probe-only tool restrictions are not workflow defaults. The writer needs its authorized command/editor capability to claim and adjudicate. These opt-in Bash observations add bounded synchronous hook work and retain only native metadata and a command digest, never tool inputs or outputs.

The hook checks its native ancestor and version, captures OS start identity and inherited inbox credentials, and creates `registration.json` only after installing and verifying an explicit owner-only Windows ACL. A repeated SessionStart for the same session/process preserves the registration generation; a different generation is refused. Registration contains a token and must never be committed, posted or copied into an envelope.

`receipts.jsonl` is atomically replaced under a bounded local writer lock. Compaction preserves append order while selecting the initial SessionStart, 512 recent records, up to 1024 marker-bearing records with matching final batches, the latest Stop/SessionEnd/UserPromptSubmit boundaries, and outstanding tool admissions. Those boundaries prevent aged acknowledgment evidence from appearing current after its prompt ended. A 4096-record or 2 MiB capacity breach refuses the write and preserves the previous file; inspect the pending job rather than deleting evidence to make room. MessageDisplay stores native metadata and marker lines only; ordinary non-final batches write nothing. A marker can precede an empty final batch: reconciliation matches both by native message and turn UUID. [Native MessageDisplay batches](https://code.claude.com/docs/en/hooks#messagedisplay-input) are synchronous, so per-invocation process startup still costs time; this opt-in observer does not claim zero-latency display. Corrupt or unavailable evidence leaves delivery pending, records a diagnostic and can recover on the same job after repair. Never discard ambiguous evidence to manufacture acceptance.

After a completed writer turn, declare `destination.host: "claude-cli-windows"`, `threadId` as its session UUID, that completed anchor's native MessageDisplay `turnId`, canonical `cwd`, absolute `registration` path, and that file's `registrationId`. Declare `writer`, `writerEffort`, and `permissions: { "permissionMode": "<actual native mode>" }` from SessionStart/Stop evidence. Preflight requires matching inherited credentials, live OS identity and native configuration; narration in the submitting turn does not invalidate the completed anchor. A fresh registration cannot silently replace the job's generation.

The outbox retains work while a newer prompt's configuration is unknown, then revalidates after Stop. Submission sends one authenticated exact-session frame with the durable UUID and `priority: "next"`. A proven refusal before any frame write records `dispatch-refused` and permits revalidation; errors after write invocation or a lost response remain uncertain and never permit blind resending. Host delivery can fold after a tool into an existing turn. Socket write/close is not acceptance: reconciliation requires transcript arrival plus a unique MessageDisplay marker and records its native turn UUID. Duplicate/out-of-order records and partial trailing rows do not trigger resubmission. Conflicting turns remain uncertain. An ended process leaves delivery pending; the adapter never launches or resumes a writer. CLI claim additionally checks inherited session credentials, OS identity and fresh native configuration.

Claude claims must use the exact supplied canonical Bash command, without wrappers or rewritten quoting, as a dedicated sole tool call. Do not run another tool alongside the claim. A later unrelated admission deliberately refuses the claim instead of selecting an earlier matching hook; this is a fail-closed limitation, not support for concurrent claim composition. The verifier reads the exact executable and argv from the durable continuation envelope, validates its job and script binding, and compares current argv and continuation environment to an unended, unique Bash PreToolUse command digest; native effort and permission metadata must match the receiving marker's prompt. It also checks the current Bash `CLAUDE_EFFORT` export. Concurrent native hooks may record the matching marker after PreToolUse; both must exist when the claim runs. Missing proof, a later prompt/Stop, closed tool use or changed configuration refuses the claim; a previous Stop is not current-turn proof. This is observational admission evidence, not an atomic native cancellation fence. Native 2.1.270 exact-claim correlation passed with a disposable empty-coverage job; this host conformance is separate from the full review/correction acceptance loop.

Native Codex launch paths use the validated directories' physical Windows identities for the private cwd, final report, completion root and isolated home. Packaged desktop hosts can expose logical AppData paths that their sandbox children cannot resolve. Canonicalization preserves the approved root identity; it does not grant new roots or alter ACLs. Actual native conformance verified public read, exact-worktree Git and permitted patches while denying protected reads and repository writes. For authorized GitHub reports, the parent obtains its existing github.com token through `gh auth token --hostname github.com` and delegates it only through `GH_TOKEN`, with `GH_HOST=github.com` and a fresh empty `GH_CONFIG_DIR` inside the private writable reviewer directory. Neither the token nor the original GitHub configuration is copied to disk or included in argv. Missing authentication refuses before reviewer launch. Actual native read-only PR access and reviewer publication passed in the reverse private-artifact loop at `a49bedb`. The integrated forward Codex-to-Sonnet review return and original-writer claim subsequently passed at `235075` ([round-two evidence](https://github.com/impowergames/impower/pull/561#issuecomment-5675166389)). These anchors describe observed workflows; a no-findings reverse review does not establish a correction.

## Running on Windows

On Windows, prefer an executable over an npm shell wrapper; an installed package entry point can be launched with Node. Supply prompts on stdin where supported or as one argument through a process API; never interpolate them into shell code. Launch background processes with hidden windows.

The npm package installs the native Claude binary at `%APPDATA%\npm\node_modules\@anthropic-ai\claude-code\bin\claude.exe`; a plan names that file as the executable with `-p --agent <definition> --effort <effort> --allowedTools Read,Grep,Glob,Bash,Write`, and the launcher supplies the prompt on stdin. When the host's command tool bounds a command's lifetime, start the coordinator itself detached from that tool (PowerShell `Start-Process node ... -WindowStyle Hidden -PassThru`, redirecting its output to files in the round's job directory) and watch its journal for the terminal row; a coordinator killed by a tool timeout leaves its reviewer running and its reservation and lock held.

Pass these reviewer executable arguments through `node scripts/agent-handoff.mjs <absolute-plan.json>` as described in [handoff execution](../review-pr/HANDOFF.md), including for one serial reviewer. Its shared slot reservation covers local participating CLI processes across worktrees until child exit. Native collaboration tasks and remote reviewers are unsupported for the enforced capacity guarantee because the launcher cannot reserve and verify their lifetime. Manual counts do not establish that guarantee; use the supported launcher or report the blocked review path.

The declared source setup home is an explicitly trusted existing native provisioning input. The launcher checks containment and bounded file presence, but does not claim that the source is owner-only or inaccessible to the sandbox. Native provisioning may require SYSTEM, administrator and sandbox-account access; the launcher never repairs those ACLs automatically. The fresh destination copy is separately owner-protected before any credential bytes are written. A protected-dummy read denial does not prove that all original Codex state is inaccessible; observed GitHub-store denial is separate evidence.

Owner-protected copied authentication and setup files remain with the retained private job as sensitive recovery data. They have no automatic deletion, expiry or revocation policy in this route. Do not share the private job directory as a public report; select sanitized evidence instead. Retention is not a claim that credentials have been erased after process exit.

Start the corrected Claude native route with a freshly registered session and private receipt store. Earlier PR prototype stores may already have reordered rows or lost final batches; the correction cannot reconstruct that history. Preserve those stores as historical evidence and do not reuse their observations for fresh admission. This restriction is separate from supported legacy awaited-handoff journals.


The completion directory is intentionally writable by the native reviewer sandbox account; it is not owner-protected evidence. Its contents are untrusted reviewer output validated alongside separately protected native results and published-report checks. Observed native CLI process exit and supervised ownership establish the tested lifecycle boundary, not universal containment of arbitrary detached descendant processes.
