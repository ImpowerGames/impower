# Supervised review continuation

Opt in only from the originating Windows Codex desktop task with its inherited authenticated app-tools endpoint. The verified route preserves that task's model and permissions and sends no overrides. Linux automatic continuation and other host adapters are unsupported in this slice; use [awaited handoff](../review-pr/HANDOFF.md). This route launches independent native CLI reviewers, never a replacement writer task. The supplied reviewer executable must remain alive for the entire review; opaque launchers that exit while detached review work survives are unsupported.

Author a JSON plan with the editor in private storage outside every checkout and Git administrative directory. `worktree` is the canonical reviewed worktree, `jobDir` a new absolute directory whose parent exists, `head` and `base` full immutable SHAs, and `pr` the PR number. Supply explicit `writer`, `writerEffort`, `reviewer`, and `permissions` as `{ "approvalPolicy": "<native policy>", "sandboxPolicy": <native policy object> }`. `destination` contains the exact originating `threadId`, `turnId`, `cwd`, and absolute native `rollout` path. Preflight verifies the rollout's session and turn identity, model, effort and permission object against these declarations and reads the authenticated host's current destination. It records only configuration fields, not raw prompts or credentials. The native rollout reader is bounded to 128 MiB; an oversized or unavailable record requires awaited mode.

`reviews` is one to four independent coverage entries: unique `id`, `transport: "native-claude-json"`, absolute native `executable`, explicit string `args`, absolute `prompt`, `effort`, and `permissions` (the native CLI permission mode). This first route requires exactly one `--model`/`-m`, `--effort`, and `--permission-mode` argument matching those declarations, plus `--output-format json`. Use native Claude review arguments inspected for the installed CLI; the reviewed route has native process lifetime rather than a detached wrapper. Before validating its report or starting another reviewer, the launcher requires a final JSON result with `type: result`, `subtype: success`, `is_error: false`, and `stop_reason: end_turn`, as well as confirmed successful process exit. A missing or interrupted result fails closed. Result inspection is bounded to 16 MiB. The prompt contains the filled review-pr contract and declared coverage. Reports from one independent first pass must not be included in another's prompt. Supply `round`, `completedReviewRound`, and the existing handoff recovery fields `reviewedHead`, `finalCorrections`, `reviewRoundLimit`, and `extendedReviewAuthorization` when applicable. Recovery never resets counts. No job authorizes another round by itself.

Before accepting a job, preflight enumerates the connected host's read/send schemas and refuses missing or changed required arguments. The supplied base must resolve to an existing commit. Private destination transport/configuration fields remain in the plan; only thread, turn and working-directory identity enter the delivered envelope. Mutation contention receives a bounded retry for worker registration, reviewer admission, cancellation and CLI claim, without retrying a host send.

Run `node scripts/review-supervisor.mjs submit <absolute-plan.json>`. Successful acceptance creates a durable job and worktree freeze, then launches a detached reviewer worker and a separate event/continuation monitor with inherited host authentication. Ending the writer turn or disconnecting a status client does not stop either process. The worker serializes the planned reviewers through the existing four-slot launcher. A monitor restart never repeats reviewer work. An ambiguous worker launch remains blocked for investigation; it is never retried automatically.

Commands take an absolute job directory:

- `status` reports durable state and evidence.
- `events <job> <cursor>` replays events after a sequence cursor. `watch <job> <cursor>` stays connected and streams new JSONL events; reconnect using the last received cursor. Every event has a stable ID and sequence. Receiving an event is separate from native continuation acceptance.
- `run <job>` starts or reconnects a monitor without launching reviewers. `recover <job>` first attempts recovery of a mutation lock using its exact OS owner identity. Live, unreadable or ambiguous owners and interrupted recovery markers remain blockers. Existing reviewer slot/lock recovery still follows the handoff procedure.
- `cancel <job>` first durably cancels the workflow and suppresses its pending outbox and subsequent reviewer launches. It then attempts workflow-specific host queue removal, followed by cooperative host turn cancellation even if removal fails or times out. The current Codex app bridge exposes neither verified operation, so both are reported as unsupported. An already running reviewer remains tracked until its actual exit; cancellation does not claim it stopped. Native Stop/Escape keeps its host meaning and does not cancel the workflow.
- `release <job>` releases a cancelled/blocked job's worktree only after its registered worker is confirmed absent and its handoff lock is absent. Unknown spawn registration remains locked for investigation. It never signals a process.

After all coverage has valid posted reports and the worker has actually exited, the monitor verifies the frozen repository, head and base and persists one continuation envelope. That envelope names the job, unique continuation ID, reports, coverage, reviewed SHAs, round, exact destination and authorized adjudication step. Submission intent is durable before the host call. A crash before or after sending never permits a blind retry: a delivery with intent is reconciled against native task items or retained as uncertain. A disconnected host preserves pending work. Active delivery may join the same originating turn; the unique ID, rather than a new-turn assumption, identifies acceptance. The bridge can hide active items until turn completion. Reconciliation examines at most ten newest-first turn pages per pass and never resends when evidence is missing, truncated or outside that bound.

The continuation instructs the original writer to run its exact `claimCommand` before changing files. Claim checks the originating task, cancellation state, unique ID, reviewer exit and frozen head again, durably records ownership transfer, then removes the freeze. Duplicate claims are idempotent. The writer reads the full paginated reports and adjudicates under review-pr; readiness still requires its normal review and CI gates. A continuation event does not mark the PR ready or authorize merging.

Retain the private `plan.json`, `events.jsonl`, `handoff.jsonl`, reviewer output/completion files and worker/monitor logs. A partial final event fails closed. A stale head, incomplete report, failed worker, uncertain ownership or changed destination cannot advance. The freeze coordinates participating launchers; ordinary external file edits are detected at validation and claim. There is no automatic cleanup or reset of ambiguous evidence.
