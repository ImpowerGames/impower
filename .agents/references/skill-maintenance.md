# Maintaining shared skills

Before changing workflow prose, inspect its callers and tests. Keep essential protections in the entrypoint and conditional details behind links at the step that needs them. Do not require readers to load every reference. After editing, run `node scripts/check-agent-tooling.mjs`; stage new checks first so Git-based discovery includes them, and review CI triggers and sparse-checkout inputs. The context-loading check validates links and entrypoint budgets; portability checks protect shared instructions and the reviewer contract; landing-pad checks protect resolve-issue's step order. Warning inventory includes references, so relocating a warning does not remove it from coverage. Update prompt-builder tests when moving the reviewer template.

For a command failure or missing procedure encountered during skill use, read [feedback reporting](feedback-reporting.md) before reporting. Prefer a driver refusal or check that prevents the mistake over a new warning. Certain fixes may accompany the active PR in their own commit, with Notes for reviewers naming them; complex mechanisms belong in the standing feedback inbox. Preserve contributor observations and stable problem/session identities.
