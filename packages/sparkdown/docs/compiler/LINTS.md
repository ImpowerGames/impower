# Lints

A lint is a warning about code that compiles but is almost certainly not what the author meant: a local that is never read, a statement no path reaches, the same condition checked twice. Sparkdown's lints for Luau code follow the rules of Luau's own linter, with Luau's messages, and each carries the rule's name as its diagnostic `code`.

The rules are in `src/compiler/lint/collectLuauLints.ts`, and the compiler reports them from `validateLints` on every compile. The specification is Luau's linter test file, `tests/Linter.test.cpp`, ported to `src/tests/luau-conformance/Lint*.test.ts`: every upstream case is there as a passing test, a skipped test for a rule sparkdown lacks, or an entry in `LintNotApplicable.test.ts` with the reason, and `LintCoverage.test.ts` checks that none is missing.

## Rules sparkdown has

| Luau lint | What it reports | Where it runs |
| --- | --- | --- |
| `LocalUnused` | A `local` that is never read. Writing to it does not count; a name starting with `_` is exempt. | Locals inside functions |
| `UnreachableCode` | The statement after one that always returns, breaks, continues or errors (`error(...)`, `assert(false)`). | Function bodies |
| `DuplicateCondition` | A condition repeated in one `if`/`elseif` chain, one `if` expression, or one `and`/`or` chain. `a and b or c` is exempt. | Luau `if` statements and expressions and Luau `and`/`or` |
| `ForRange` | A numeric `for` without a step that runs backwards, stops short of a fractional end, or starts or ends at 0 over a table's length (a bare `#t`, as in Luau). | Luau `for` loops |
| `PlaceholderRead` | A read of the placeholder `_`, local or global, including a compound write (`_ += 1`). A plain write is not reported. | Inside functions |
| `BuiltinGlobalWrite` | A write or global function definition that replaces a name of sparkdown's standard library (`src/runtime/StdLib.ts`, its functions' first path segment and its constants): `math = {}`, `function assert(x) end`, `store count = 0`. Local, member and method writes are exempt. | The whole program |
| `LocalShadow` | A used local, parameter or loop variable that hides an earlier one of the same function (`Variable 'x' shadows previous declaration at line 2`), or, hiding none, a global the program uses (`Variable 'x' shadows a global variable used at line 3`). A plain write does not use a local. A built-in global, a name starting with `_`, and a local of an enclosing function are exempt. | Locals inside functions; the global form over the whole program |
| `FunctionUnused` | A `local function` that is never read, or a global `function f()` whose name nothing in the program mentions except other `function f()` statements (`Function 'f' is never used; prefix with '_' to silence`). A call inside its own body reads a local function; any other occurrence of a global's name, a write included, uses it. A name starting with `_` is exempt; methods and members (`function T:m()`, `function T.f()`) are not reported. | Local functions inside functions; global functions over the whole program |
| `SameLineStatement` | A second statement on the same line without a semicolon after the previous statement, once per line. A local followed by a `do` block is exempt. | Luau statement blocks |
| `MultiLineStatement` | A continuation expression that begins no farther right than its statement, once per statement. Table contents and `repeat` conditions are exempt. | Luau statement blocks |
| `UninitializedLocal` | A `local` its statement gives no value (`local x`, or a name past a value list that ends in neither a call nor `...`) that no assignment or `function x()` statement writes, at its first read (`Variable 'x' defined at line 2 is never initialized or assigned; initialize with 'nil' to silence`). A compound write (`x += 1`) reads it; a name in a type (`typeof(x)`) does not. | Locals inside functions |
| `UnbalancedAssignment` | A `local` statement or an assignment with more values than names (`Assigning 3 values to 2 variables leaves some values unused`), or fewer when the last value is not a call, `...` or `nil` (`Assigning 2 values to 3 variables initializes extra variables with nil; add 'nil' to value list to silence`). | Luau `local` statements and assignments |
| `DuplicateFunction` | A function statement or `local function` whose name an earlier one in the same block already defines (`Duplicate function definition: 'f' also defined on line 2`), a member named with its receiver (`'T.x'`, a method included). Definitions in separate blocks, such as the arms of an `if`, are not compared. | Every Luau block; members of a global table over the whole program |
| `DuplicateLocal` | A name that one `local` statement or one function's parameter list declares again, at the later one, against the earlier one's column on its line (`Variable 'a' already defined on column 7`) or its line otherwise (`Function parameter 'a' already defined on line 2`), and an explicit `self` parameter of a method (`Function parameter 'self' already defined implicitly`). `_` is exempt. When only the later name is read, `LocalUnused` reports the first. | Every Luau `local` statement and function |
| `GlobalUsedAsLocal` | A global that a plain write or `function g()` statement assigns and that only one function uses, every reference inside it (`Global 'total' is only used in the enclosing function 'tally'; consider changing it to local`, or `... the enclosing function defined at line 2` for a function without a name), and otherwise one that every function writes before reading it and nothing writes outside a function (`Global 'x' is never read before being written. Consider changing it to local`), once, at its first reference. A global a `store` or a top-level `const` declares, a built-in and `_` are exempt. Luau's upstream test cases call it `GlobalAsLocal`. | Globals over the whole program |
| `TableLiteral` | A table constructor's string field or integer index that an earlier item already has (`Table field 'first' is a duplicate; previously defined at line 3`, `Table index 2 is a duplicate; previously defined at line 4`) or that a list entry already fills (`Table index 1 is a duplicate; previously defined as a list entry`), and a table type's property that an earlier one already has (`Table type field 'first' is a duplicate; previously defined at line 24`). A `read` and a `write` property of one name are not duplicates; one that overlaps another's access is (`Table type field 'x' is already read-write; previously defined at line 4`, `... already has a read type defined at line 6`). A key in parentheses and a fractional, negative or larger than 32-bit index are not compared. | Every Luau table and table type, in types too |
| `TableOperations` | A call of the global `table` library that is likely a bug: `table.insert(t, #t, v)`, `table.insert(t, #t + 1, v)`, index 0 in `insert`, `remove` or `move`, `table.remove(t, #t - 1)`, `table.create(n, {})`, and `table.insert(t, f())` where `f` returns more than one value. Parentheses around the argument silence it. | Every Luau call outside a type |
| `DeprecatedApi` for `getfenv`/`setfenv` | A call of the global `getfenv` or `setfenv` with a literal number as its first argument (`Function 'getfenv' is deprecated; consider using 'debug.info' instead`, `Function 'setfenv' is deprecated`). It is an Information diagnostic tagged Deprecated, like the compiler's other deprecations, not a Warning. | Every Luau call outside a type |
| `ImplicitReturn` | A function with a `return` of values that can also reach its end, at its last statement or the `end` closing it (`Function 'f' can implicitly return no values even though there's an explicit return at line 3; add explicit return to silence`, without the name for a function value). A final `error(...)` or `assert(false)`, a `while true` or `repeat ... until false` without a `break` of its own, and a nested function's returns do not count. | Functions |
| `MisleadingAndOr` | An `a and false or b` or `a and nil or b`, whose first alternative is always falsy, over the whole expression (`The and-or expression always evaluates to the second alternative because the first alternative is false; consider using if-then-else expression instead`, or `... is nil; ...`). Parentheses around the `and` or around the literal silence it, as in Luau. | Every Luau expression outside a type |
| `ComparisonPrecedence` | A comparison whose left side is an unparenthesized `not`, unless its right side is one too (`not a == not b`): `not X == Y is equivalent to (not X) == Y; consider using X ~= Y, or add parentheses to silence`, or `... add parentheses to silence` for an ordering. And a comparison whose left side is another comparison: `X <= Y == Z is equivalent to (X <= Y) == Z; add parentheses to silence` when either is an equality, `X <= Y <= Z is equivalent to (X <= Y) <= Z; did you mean X <= Y and Y <= Z?` otherwise. Over the whole expression; parentheses silence it, as in Luau. | Every Luau expression outside a type |

The arms of Sparkdown's narrative `if`/`elseif` blocks around dialogue and actions are not compared with each other; their conditions and the Luau inside them are checked like any other. The `if` and `for` control flow of Sparkle `layout` blocks is a separate construct in the grammar and is not checked.

Sparkdown also has warnings that correspond to two more Luau lints, in its own wording:

| Luau lint | Sparkdown |
| --- | --- |
| `UnknownGlobal` | `Cannot find variable named ...`, for a read of a global that no script declares or assigns, at the top level and inside a function. |
| `DeprecatedGlobal`, `DeprecatedApi` | An Information diagnostic tagged Deprecated for Luau's deprecated stdlib entries (`unpack`, `table.getn`, `table.foreach` and others), naming the replacement. |

The warnings sparkdown gives for its own syntax (unknown Sparkle events and props, unknown rich text tags, blank choices) are listed in `LintSparkdownWarnings.test.ts`.

## How the rules differ from Luau's

The rules walk the Luau AST that `src/compiler/typecheck/readLuauAst.ts` reads from the syntax tree the editor highlights, the reading the type checker checks (see `TYPECHECK.md`), so a name is a local where Luau would bind it, as Luau's parser resolves it, and an expression has Luau's shape. Where they differ from Luau's linter:

- Besides the units the type checker reads, the rules read the Luau expressions in Sparkdown's own text and constructs: an interpolation (`{a and b}`) or a call shorthand (`{{f(a or b)}}`) in a line, a line of dialogue, a choice or a line inside a narrative block; a divert's arguments; an alternator's selector (`match (a and b)`, `plural(n)|...`); a Sparkle handler and the statements of its `{ ... }`; and a property's value or a method in a `define`. Each expression that holds an `and`/`or` chain, an `if` expression or a function is read on its own, and each `if` or `for` statement is read as the body of a function.
- `LocalUnused`, `UnreachableCode` and `PlaceholderRead` read every Luau function a script holds, a definition (`function f()`) or a value (`local f = function() end`, an argument, a `define`'s property), and a `define`'s method (`greet() ... end`, whose `function` Sparkdown leaves implicit), wherever it is written, each once. A function with a block missing its `end`, whether being typed or cut short, is not checked: the reading takes a later `end` as that block's, so the function does not hold what the author wrote.
- `LocalUnused` does not check locals outside functions. Top-level code is narrative with embedded logic, and a top-level local can be read from places the rule cannot scope (interpolated text, later narrative). `PlaceholderRead` does not check reads outside functions, for the same reason.
- `LocalUnused` does not report a `const` outside every function, which is the story's published constant, a global; a `store` declares a global too. A `const` inside a function, a Sparkle handler included, is Luau's local, and an unused one is reported as a local is.
- The grammar reads some names as Sparkdown's structural words (`style`, `layout`, `match`) even where the author meant a name (`setStyle(style)`, `if match then`), and the reading has no name there. `LocalUnused` counts such a word, after a local's declaration in its function, as a use of the local it names, so a use is never missed (#984).
- `LocalShadow` exempts names starting with `_`, which Luau exempts only from its unused-local warnings. Its global form looks at the whole program: a global read or written in another script, a narrative line, an interpolation or a Sparkle handler counts as used. The message names the first use in the local's own script, as Luau's does; with none there, it names the first by script URI and then position in another script, and adds that script's path, relative to the main script's folder as an `include` line names it: `Variable 'x' shadows a global variable used at line 3 in 'chapter.sd'`. Built-ins are the standard library's names and the globals and type names of the builtins prelude. The global form reruns over the cached facts on every compile, so a script's warning comes and goes as other scripts change or leave the program. It is silent for a name declared as a `local` or `local function` in a unit's outermost block in any script (such a local can reach later scenes and including scripts, which the reading does not show) or that the grammar reads as a keyword somewhere in the program. It does not count a reference on a line with a syntax error (an integer literal's `i` suffix reads as a name), nor, in an expression read outside every unit (an interpolation, a Sparkle handler, which are read without the locals around them), a reference that a local of its name declared outside that expression in the same script could reach, or that names a parameter of the scene or branch it is in, up to that flow's `end`. A reference in a unit's or a handler's own Luau is bound as Luau binds it, so `local x = x` reads the global. A story constant (a `const` outside every function) is a global, so a local named like one is reported against the constant's uses. A keyword reading of the name inside the function silences the local form. As in Luau, a parameter or loop variable hiding another is not reported unless the hidden one is a loop variable never used, and a local declared by the same statement as the one it hides, or a local function hiding a local function, is left to `DuplicateLocal` and `DuplicateFunction`.
- `FunctionUnused`'s local form checks local functions inside functions only, as `LocalUnused` checks locals, and not in a function holding a syntax error: recovery can end the function early (at a Luau `class`, which the grammar lacks) and read the calls after it as narrative. A keyword reading of the name inside the function counts as a use, as for `LocalUnused`. Its global form looks at the whole program: a read or write in another script, a narrative `&` line, an interpolation, a divert's arguments or a Sparkle handler uses the function. It reruns over the cached facts on every compile, so a script's warning comes and goes as other scripts change or leave the program. Because the warning concludes from an absence, it is also silent for a name the grammar reads as a keyword somewhere in the program, for one that a script spells where the reading placed no name in Luau or Sparkle syntax (a bare `@click=f` handler, a `define`'s value), a divert's path or a Luau string, for a name defined anywhere inside a statement holding a syntax error or a block missing its `end` (such a statement can end early, or run on past the calls after it), for a name any script holding such a statement mentions outside a comment, even in what reads as narrative (recovery there can turn a call into narrative), and for the builtins prelude's globals and type names. A mention in dialogue, a choice's text or a comment is not a use. As in Luau, the name warns once per script, at its last definition there; a `store function` is a function statement on a global too.
- `UninitializedLocal` checks locals inside functions only, as `LocalUnused` does, and not in a function holding a syntax error, whose reading can lose a write. A name the grammar reads as a keyword inside the function (`match = 1`) may be a write the reading lacks, so it silences the local of that name.
- `UnbalancedAssignment` reads every Luau `local` statement and assignment in a script, in functions or not, as `DuplicateCondition` reads conditions, and the statements of a Sparkle handler. A `store` is not Luau's assignment and is not checked. It leaves alone a statement on a line holding a syntax error (recovery ends `local k = 1, m = 2` at `m`) and one inside an outermost statement holding a syntax error or a block missing its `end` (a story loop's range on the line after its header reads as an assignment).
- Unlike Luau's parser, the reading does not end a block at a `return`, `break` or `continue`: Sparkdown reads the statements after one as its block's, and `UnreachableCode` reports the first of them.
- `DuplicateCondition` and `ForRange` read every Luau `if` statement and expression, `and`/`or` chain and numeric `for` in a script, in functions or not, Sparkdown's narrative blocks included (`if`, `while`, `for`): a narrative block's condition and the Luau inside it are read, but the conditions of a narrative `if` block's arms are not compared with each other.
- `BuiltinGlobalWrite`'s built-ins are sparkdown's standard library, not Luau's: `count` and `plural` are built-ins here, and a Luau global sparkdown lacks is not. It runs over the whole program after every compile, from the cached name facts. Where Luau resolves the local a write reaches, the reading cannot see across units: a script's top-level `local` can be visible to its later scenes and callbacks and to the scripts that include it. So a `local` or `local function` of the name in a unit's outermost block (outside every function, Sparkle handler, `do`, `if` or loop body), in any script of the program, or an occurrence of the name the reading could not place (a grammar keyword), silences every plain write and function definition of that name except one earlier in the same block as the local, which the local cannot reach; an explicit `store` or top-level `const` still warns, since it declares the global itself. A top-level `function` named after a built-in also gets the compiler's existing error that a built-in cannot name a function.
- `DuplicateFunction` does not compare plain-named functions in a script's top level, where the reading also places the functions written in scenes and branches: the compiler makes each a story function, and already reports a second of the name, in the same script or another, as an error (``Duplicate identifier `f`. A function named `f` already exists on line 1 of 'main'``). Members of a table there are compared, and those of a global table (a `store`, a global assignment or a story constant) across the whole program too, since every script's top level is one scope: a script's first `function T.x()` warns against the first in another script, the first by script URI and then position, naming that script's path as `LocalShadow` does (`Duplicate function definition: 'T.x' also defined on line 2 in 'chapter.sd'`). The program-wide form reruns over the cached facts on every compile, so the warning comes and goes as other scripts change or leave the program. A block missing its `end`, a function holding one, a statement holding a syntax error (with every block in it), code written in a type and a name the grammar reads as a keyword in the block (or, for the program-wide form, anywhere in the program) are left alone. Luau treats a first definition at the very start of a file (line 1, column 1) as absent, so it reports a third definition there but not the second; Sparkdown compares every definition.
- `DuplicateLocal` reads every Luau `local` statement and function in a script, in functions or not, as Luau does; a function written in a type is not read, as in Luau. A scene's or branch's parameters are not Luau's and are not checked, nor is a story constant (a `const` outside every function), which is a global. A syntax error in the name list, from the start of the statement or function to its first value or its body, or to the end of its line for a `local` without values, which recovery may have ended early (`function g(a, a, b c)`, `local x, x, y. = 1, 2, 3`), leaves the list alone, since recovery there can read a list the author did not write, and so does a parameter list missing its `)` (`function g(a, a end`); an error in a value or a body (`...` outside a vararg function) does not change the names. A name written after the list without a comma (`local x, x, y z = 1`) starts the next statement, as Luau reads it, so the list before it is still checked. The rule concludes from two names the reading holds, so a name the grammar reads as a Sparkdown keyword, which the reading lacks, can hide a warning but never make one.
- `GlobalUsedAsLocal` matters more than in Luau, since an accidental global is story state that goes into save files, and so does a false warning. It looks at the whole program: a reference in another script, a narrative `&` line, an interpolation, a scene's or branch's Luau or a Sparkle handler is outside every function. A top-level `function f()` is a function, as it is in Luau, so a global only it uses is reported. Luau does not count a read outside every function as a read before the write; Sparkdown does, since narrative may read the story's saved state there. Luau marks an assignment's targets written before reading its values; Sparkdown reads the values first, so in `x = x or 0` the read can see an old value. Luau resets a global's "defined outside a function" when a later `function g()` statement inside a function defines it again; Sparkdown keeps it. Because the warning concludes that no other use exists, it is also silent for a name the grammar reads as a keyword somewhere in the program; one a script spells where the reading placed no name in Luau or Sparkle syntax (a bare `@click=f` handler, a `define`'s value), a divert's path or a Luau string, though a member's name, a table's record key and a table type's property (`t.score`, `{score = 1}`, `{score: number}`) never name a variable and do not count, except a member of the globals table (`_G.score`, `(_G).score`, `(_G :: any).score`), which does; one any `.luau` file mentions, since the pass reads a `.luau` file's lines outside its functions as narrative; one declared as a `local` or `local function` in a unit's outermost block in any script; and one with a reference on a line with a syntax error, inside a statement holding a syntax error or a block missing its `end`, in an expression read outside every unit that a local could reach, or in a type, which Luau's linter does not walk. It reruns over the cached facts on every compile, so a script's warning comes and goes as other scripts change or leave the program. When the global's references span scripts, the warning goes to the first by script URI and then position.
- `TableLiteral`, `TableOperations` and `DeprecatedApi` read every Luau table and call in a script, in functions or not, as `DuplicateCondition` does. A table, table type or call holding a syntax error is left alone, since recovery can read items or arguments the author did not write. `TableLiteral` compares a table type's properties as Luau's new solver does, which sparkdown's type checker follows, so `{read x: number, write x: number}` is not a duplicate. As in Luau, `TableLiteral` also reads tables written in a type (`typeof(...)` included), and the other two leave code in a type alone.
- `TableOperations` reads only syntax, as Luau's does but for one check: `table.insert(t, f())` needs `f`'s type to know it returns more than one value. Sparkdown warns only for the standard library functions whose Luau type returns more than one value before any variadic tail, called through their global library (`string.find`, `string.gsub`, `math.frexp`, `math.modf`, `utf8.len`, `utf8.codes`, `coroutine.close`), and is silent for any other call, an author's function or a method included. A bare global function (`next`, `pairs`) is left out, since a function statement of that name could replace it. Luau's other half of the rule, `#` or `ipairs` on a table without an array part, needs the type checker and is not implemented.
- `DeprecatedApi` for `getfenv`/`setfenv` reads only a literal number as the first argument (`(1)` is not one); Luau also reports one the type checker types as a number.
- `ImplicitReturn` reads the functions `LocalUnused` reads, and each function inside them, but not a function written in a type, which Luau's linter does not walk. A function holding a syntax error or a block missing its `end` is left alone, with every function in it: recovery can read statements the author did not write (a missing `then` reads the `return` after it as the `if`'s body). Scenes, branches and narrative blocks are not functions and are not checked. Luau reads only `true` as a `while` guard that never ends the loop; Sparkdown also reads a literal number or string, which is as truthy (`0` and `""` included), so `while 1 do ... end` without a `break` does not warn.
- `SameLineStatement` and `MultiLineStatement` use the statements and expression boundaries of the existing AST, including functions in interpolations and properties. `SameLineStatement` also checks narrative `&` logic lines, which are bounded to one line; multiline continuations belong in supported multiline Luau contexts, such as actual function bodies (see [why the grammar has paired rules](GRAMMAR.md#131-why-pairs-exist)). Narrative text is excluded. Syntax errors and incomplete blocks are left alone because recovery can change those boundaries. The two diagnostic names are distinct, as in Luau.

The pass runs over whole scripts rather than inside the incremental annotators, since a lint depends on lines far from the one it reports. The compiler caches each script's diagnostics and name facts until its syntax tree changes. Structural extraction uses Lezer's public `Tree`/`TreeBuffer` representation to select Luau nodes without building a cursor for every narrative word and grammar capture; embedded expression ASTs and narrative-if offsets are read once per tree. The rules themselves still execute on each direct call to `collectLuauLints`.

## Shared name facts and program index

`src/compiler/lint/luauNames.ts` collects names from the converter AST that the type checker reads, with the same `AstLocal` objects for declarations and references. `LuauScriptLints.names` distinguishes local declarations and parameters, global definitions, reads, plain writes and compound writes. It retains each reference's authored enclosing function and each declaration's AST block identity. A reference also keeps every authored function around it, outermost first, and whether it is written in a type; a global read keeps whether a plain write of the global earlier in its function, outside any `if` or loop, always precedes it (`dominated`, after Luau's GlobalUsedAsLocal). `LuauNameFacts.functionStarts` holds where each authored function begins. A `store` or a `const` outside every function remains an explicit global definition; a `const` in a function is a local declaration, as Luau's is (`LocalUnused` reports it unused as it reports a `local`); a property write reads its receiver and index rather than writing the receiver's name.

An embedded `store` keeps the same explicit global status as a normalized document-unit store, including its function value when present. A published `const`'s checking binding does not introduce a runtime local: references follow its existing `AstLocal.shadow` chain to a real local when one remains in scope, while retaining the original expression node. Otherwise the reference is global. This applies to plain and compound targets and member receivers as well as reads.

Authored function statements also retain their qualified paths and receivers, the local binding identity where applicable, and whether they are methods. Separate `if` arms keep distinct AST block identities. Synthetic wrappers used to read scene/branch units or Sparkle handler statements are not authored declarations, functions or enclosing functions; their authored parameters and nested functions retain their original identities. A flow wrapper's exact synthetic binding is classified as a runtime global when an authored name collides with it, because that checking-only local is absent at runtime; real authored locals of the same spelling remain local.

Declaration `scope` is the owning AST block: parameters and loop variables use their function or loop body, and ordinary locals use the block containing their declaration. Binding identity remains the converter's authority for visibility, including a `repeat` body's locals in its `until` condition. Parser recovery identifiers such as `%error-id%` are excluded from name facts and unused-local warnings.

The facts include all document units and embedded Luau access paths and expressions in narrative text, interpolations, call shorthand, define values and Sparkle handlers. Standalone embedded expressions use the converter's existing reading, which classifies their names as globals; this pass does not add a second parser or scope resolver.

The grammar can mark a valid use of `style`, `layout` or `match` as a structural keyword, leaving no corresponding name expression in the converter AST. `LuauNameFacts.uncertainNames` records these unrepresented keyword occurrences with their exact name, range and `grammar-keyword` reason. It excludes represented declarations, definitions and references and Luau reserved words; soft keywords are not blindly treated as reserved. These occurrences have no AST node, binding or access classification. They are cached by tree and recombined into the separate `LuauProgramNames.uncertainNames` map with script URIs; they never create definite global entries or reads. Each declaration also records `scopeTo`, the document offset where its block ends.

Rules drawing conclusions from absent uses, enclosing-function exclusivity or initialization must consult same-name uncertainty and suppress unsafe warnings. An uncertain occurrence alone must not activate `LocalShadow` or invent a global use. File/program-wide conservatism may suppress a warning that fuller AST coverage would permit; avoiding false warnings takes precedence. The existing `LocalUnused` keyword workaround remains in place, so this contract adds neither warning rules nor a separate parser or lexical resolver.

`LuauScriptLints.roots` exposes those same cached AST roots and their `offsets.range(location)` mapping for expression-based rules. Handler statement roots omit their synthetic function wrapper. Flow roots preserve the complete converter root and identify their exact checking wrapper with `syntheticFunction`; name facts use this provenance rather than filtering any authored name. Consumers can visit these roots without discovering or parsing embedded candidates again.

`SparkdownCompiler.validateLints` combines the current scripts with `indexProgramNames` on every validation. The returned index holds definitions, reads and writes by global name, with script URIs, plus authored function definitions and the per-script facts. Recombining the current script set removes deleted scripts and uses immediately, while unchanged trees retain their fact and local identities. These are shared prerequisites for name-based warning rules; this index introduces no new warning rule by itself.

## Checking for false positives

Every change to a lint runs the corpus script and reads what it reports:

```bash
node packages/sparkdown/scripts/lintCorpus.mjs --project <path-to-R&B>/project > findings.txt
```

It compiles every tracked `.sd` file in the repository, Luau's vendored conformance files (each wrapped in a function and compiled as a `.sd` script, with line numbers still those of the `.luau` file; the wrapper's own FunctionUnused warning is not printed, and GlobalUsedAsLocal is read at Luau's module level, rerun with the wrapper dropped from every reference's enclosing functions, so both its messages can report and a "defined at line N" names the file's own line) and, when `--project` is given, a project such as R&B as one program. It prints each lint as `file:line:column Code message`, in a stable order, and a count per corpus on stderr. Every finding it prints is read in context, and the output is diffed against a run on the base commit to see exactly what a change added or removed.

## Rules sparkdown lacks

Each has its upstream cases ported as skipped tests, ready to be enabled by an implementation.

| Luau lint | Test file |

## Rules sparkdown omits

These depend on Luau features sparkdown does not have, and are listed with their reasons in `LintNotApplicable.test.ts`:

- `--!` directive comments: `--!nolint`, `--!optimize`, and the `WrongComment` lint that checks them. A `.luau` file's `--!strict`, `--!nonstrict` and `--!nocheck` set its type checking mode, and the type checker reports the half of that lint that concerns them (`CommentDirective`, see `TYPECHECK.md`).
- `@deprecated` and `@native` function attributes, and `RedundantNativeAttribute`.
- Lints that need the type checker (#589): `UnknownType`, the typed half of `DeprecatedApi`, `TableOperations` on indexers, typed `FormatString`.
- `ImportUnused`, which is about `require`; sparkdown has no modules.
