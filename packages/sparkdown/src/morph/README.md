# Morph bake

A `morph` declaration (see `../compiler/morph/`) says how a portrait moves between its drawn states. This directory turns that declaration and one image variant's artwork into an artifact a player can animate: ordered render parts, numeric frames for every moving drawing, the apertures that clip eyeballs and shadows, and a static rest render with those apertures applied. The geometry itself comes from `@impower/spark-morph`; this code finds the drawings, decides what pairs with what, and packages the result.

Every host runs the same code. The bake (`bake.ts`) is a pure function of the artwork text, the variant's attribute selection and the morph's recipe. Hosts differ only in where the artwork comes from and who keeps the result (`hosts.ts`, `assetService.ts`).

## What compilation emits

Compilation never bakes. Binding a morph to images needs only the attribute vocabulary, which every host has, while baking needs the SVG source, which the web editor's compiles do not carry. So the compiler fills `program.morphs` (`channel.ts`) with these tables:

- `recipes`: each morph's `MorphRecipe` as canonical JSON, once per morph. A recipe holds the transition policies, the keyframes' state selections, the states its `rest` block gives driven groups and the clip entries after inheritance. `rest` is sorted by group and left out when the morph writes none, so a morph without it keeps its recipe text; a group it leaves out rests in the state of the last keyframe naming it, which the recipe already holds. A root `depth` of `rest`, the default, is left out of the text, so a morph that keeps it has the recipe it would have without the field. A drawing `spread`, at the root and under a label, is a number of pixels; the root's is left out at `0`, and a label's `0` is kept only where the recipe records another drawing `spread` it would otherwise take, so a morph that writes none, or writes `0` everywhere, keeps its recipe text. Its `paints` entries keep their authored order with each colour written as `formatColor` writes it and each `opacity` as a number from 0 to 1, so equal colours and opacities give one recipe; a morph with none leaves the field out. A label's `partner` is a list in written order, each label once, and is left out when unset, when it names only the label itself, and on a label a clip lists in `between`, so a morph without it keeps its recipe text. `motion` lists, sorted, the labels whose containers in the keyframes set a layer property the grammar in `motion.ts` accepts, and is left out when there are none. Timing and the property values are not in it, so retiming a blink or retuning a distance does not invalidate any baked geometry.
- `variants`: for each image variant morphs play on, the `MorphRef`s keyed by the variant's context name, the name an image directive resolves to. A morph plays on a variant (an `active` binding, `bindVariant`) when its `when` and `unless` admit the variant and every visible folder that draws a driven group draws each state the keyframes and `rest` name for it, except that a switch group (whose only options are `on` and `off`) needs no drawing of `off`, since its `off` pose shows none of the group's `on` layers; what the variant rests in does not matter. A condition holds when the variant's selection, or failing that a `default`, chooses the state in a visible folder drawing the group. States match exactly. A variant the conditions keep out is `excluded`, silently; one a folder does not fit is `skipped`, reported on the morph. A morph that leaves a driven group out of its first keyframe, which validation reports as an error, has no starting state for that group and gets no references.
- `conditions`: each morph's `when` and `unless` states, written with their groups, for the morphs that have any. They decide which variants get references and are not part of the recipe, so editing them prepares no artwork again. `morphRefsForStruct` reads them to bind a look the compile did not list.
- `speech`: each `trigger = speech` morph, with `default: true` for the one marked `default = true`. A child's mark is its own: `default` is not inherited through `as`, in the compiler's effective morph or in the engine's define chain (`MORPH_OWN_FIELDS`).
- `picks`: for each variant a speech morph plays on, the references for each pick a directive's `morph` clause can make, keyed `none` and by every speech morph that plays there. `variants` holds the references for a directive with no clause.

A directive's pick decides which speech morphs play on each image it shows (`chooseSpeechMorphs`). The speech morphs that play on a variant fall into sets that drive a shared group; morphs that are not speech morphs always play. In each set the one the clause names plays, or failing that the one marked `default`, or the set's only member. `none` plays no speech morph. A set where none of these decides is ambiguous: nothing plays on the image, and compilation warns once on each morph of the set, naming an image. A pick that names a speech morph in no set of a variant leaves that variant to the default rule.

A directive's pick is `none` on a line its image's character does not speak (`linePick`): when a layer belongs to a character, through its image or itself, and the line's cue does not name that character, narration included, the directive's own clause is replaced by `none` for that layer. A layer that belongs to no character keeps its clause. The line is the beat the directive is shown in: the engine merges a line that writes no text into the next line's beat (`InterpreterModule.appendBeat`), so a directive on a line of its own belongs to the next display line. The engine reads the beat's cue (`cueCharacter`, over `readCue`) and passes the beat's speaking character to the image write. The editor does not decide which line a directive is shown with: the compiler's scan reads every look with the pick `none`, so a speech morph's rest gives no override warning on any script line or named look, and the language server's hover and suggestion previews give a directive the pick `none` (`directiveOwnLookPick`), so they show the directive's own look. The decision is per image and per layer: the image write stores the beat's speaking character on each image event (`speaker`, empty when nobody speaks) beside the directive's own `morph`, and the render decides each layer from the owner of its image, or else of the layer itself, the written pick and that speaker, so a composition and a layered image of several characters split by character and a kept portrait restores as its line showed it. An event saved without `speaker` renders with its written pick, as it did before.

The look a variant shows (`shownLook`) is its selection with each playing morph's rest in the groups it drives (`poseSelection`): a group keeps the look's own selection where every visible folder drawing it already chooses the rest state, which leaves the image's attributes as they were, and takes the rest state otherwise. The compiler's scan of script lines and named looks reads its attribute diagnostics from the look with no speech morph and warns on a choice the rest of a morph that is not a speech morph replaces; the engine writes the image in the look of the line it is shown on (`shownImageLayers`), and the language server's hover and suggestion previews show a directive's own look until the rest render is ready.

Two morphs overlap when they drive the same group, move the same label, or name the same label in a clip's `between` or `targets` (`morphOverlaps`). The morphs that play on a variant and do not overlap share one reference, a set, which every host bakes into one artifact; when any two of them overlap, each keeps a reference of its own, and the engine keeps the image still (see Playing in the web player).

A reference is about 600 bytes on a served host for one morph and less where the art is inline. It names its morphs in name order, the root image, the variant's canonical selection and the groups the morphs drive, plus a `key`. The key is a hash of the bake format, the artwork's version (its served `src`, which carries the file signature, or a hash of the inline data), the selection and the text of every recipe in the set, so anything that would change the artifact changes the key. Excluded variants (a look the morph's `unless` or `when` keeps out) and skipped ones get no reference; compilation reports skipped ones on the morph block.

The channel is built on every compile, with or without validation, and reused while the context revision and the effective morphs are unchanged. It is a separate channel rather than a field on the `filtered_image` structs because those structs are shared between compiles and may only carry derivations of their own inputs, while a reference also depends on the script's morph declaration.

## Resolving a reference

`createMorphHost` resolves a reference through one `MorphBakeService`:

- With `ref.src` and a `fetch`, the asset service bakes. In the web editor `src` is the variant's filtered-image URL (`/file:/…svg?v=…&attributes=…`) with one `&morph=<recipe>` for each morph of the set, in name order, and `&key=<key>` appended. The service worker (`impower-dev/src/workers/sw.ts`) and the dev server's mirror both answer it with `serveMorphAsset`: the artifact as JSON, or with `&morph_output=rest` its rest render as SVG. A request whose recipes are out of name order, repeat a name or overlap is refused. The worker caches artifacts in the `morph-artifacts` bucket by the file's content digest, the selection, the recipes and the bake format, never by the request URL. One file, selection and set of morph names is one consumer: writing its new artifact deletes the ones an older signature or older recipes of those morphs left, and past `MORPH_ARTIFACT_CACHE_ENTRIES` the oldest entries go. Like the filtered images beside it, the service bakes the file as it is when asked, so a reference minted before an edit gets the edited art's artifact under its own key until the next compile mints the new one. A page abandoning its request does not stop the worker's bake, which finishes and is cached for the next request.
- Without `src`, the host reads the artwork itself and bakes in process: `inlineMorphSource` reads the program's inline `image.data` (VS Code, local compiles), `fetchedMorphSource` fetches the root image's `src` (a player with plain file assets). The language server reads its watched files directly, because it holds every artwork's text on every host.

Readiness is static first. A consumer keeps showing the variant's ordinary filtered source (the `src` that `filterImage` returns) until the artifact arrives, and keeps it for good if resolving fails. `MorphArtifactSlot` packages this for one consumer: `set(ref)` starts a request and abandons the previous one; a result whose key the slot no longer holds is released unseen, so a late bake for an older source or recipe generation never attaches; a failure leaves the slot `failed`, which means "stay static".

Cancellation is per consumer. Aborting a request rejects that caller only; the shared bake is cancelled when no caller is still waiting for it, and the bake observes that between drawings. A caller arriving after everyone else abandoned a bake starts a fresh one.

## Caching and lifetime

`MorphBakeService` coalesces concurrent requests for one key into one bake and reference-counts what it keeps. A `MorphHandle` holds one reference until `release()`. Unreferenced artifacts are evicted oldest-use-first once the service holds more than `maxArtifacts` artifacts or `maxBytes` of unreferenced ones; referenced artifacts are never evicted. `handle.url(…)` creates an object URL for the rest render or a part on first use, and the service revokes it when the artifact leaves the cache. `onEvent` reports each bake (with its time and size) and each eviction, so a host can watch its cache. `invalidate` drops the artifacts of an edited or deleted artwork; one still held goes when its last handle is released, and new requests bake again. Edits change keys anyway, so invalidation only returns memory sooner.

Reusable geometry is kept apart from consumer-specific artifacts. The service keeps one geometry cache per artwork content (bounded by `maxSources` and `maxGeometryPerSource`) holding the root-space morph result of each drawing pair and method (failures included, so a cached bake reports what a fresh one would), its sampled frames in each element space, and the aperture samples of each edge set. Variants of one artwork that differ in groups the morph does not drive (an outfit, a gaze) reuse all of that instead of searching for the same correspondences again; only parts and visibility are rebuilt, a few milliseconds on the test fixtures against hundreds for a first bake. The cache is keyed by drawings, not by morphs, so baking a set that shares a morph with an earlier bake searches only the pairs its other morphs move. The defaults in `MORPH_CACHE_DEFAULTS` are starting bounds, not measured budgets.

## What a bake does

A bake takes the recipe of every morph in the reference's set and prepares one artifact for all of them. Each driven group belongs to the morph whose keyframes name it, and everything about a drawing that changes with that group (its schedule, its `layers` policies, its `partner` list, `depth` and `spread`) comes from that morph's recipe. The set's clips, `paints` entries and moved labels are all applied, each clip's apertures following the segments of its own morph's groups. A set of one morph bakes as that morph alone.

1. Reads the artwork with the attribute module's own walk, so every element carries the layer key visibility is evaluated with. Artwork carrying a style sheet, or markup that may bring one in (a `<style>` element anywhere, empty or not, any `<link>` element, since its relationship can be spelled with character references, an `<?xml-stylesheet?>` instruction, or a DOCTYPE with an internal subset, whose entities a browser expands into markup) keeps its static render with one `unsupported-element` error: a sheet's rules could decide which drawings show, what composites and what each part references, and the bake reads only attributes and inline `style` attributes.
2. Binds the variant to each morph by the fit rule compilation used (`bindVariant`); a recipe carries no conditions, which compilation has already applied. A variant one of them no longer fits, because its art changed since compiling, bakes to a static artifact with a diagnostic naming that morph. A static artifact's rest render, like a live one's, is the variant in its shown look.
3. Builds each driven group's schedule from its own morph's keyframes. Each group's rest is the state the recipe's `rest` gives it, else the state of its last keyframe (`morphRestPose`); a keyframe state equal to the rest is the rest pose. A schedule whose first pose sits after offset 0, or whose last sits before 1, holds the rest there, as in CSS. A rest state no keyframe names joins its group's states with no segment: nothing moves into or out of it, and the player cuts to it. Every pose is a selection (`poseSelection`): the variant's own where every visible folder drawing the group already chooses the pose's state, and the pose's state otherwise.
4. Evaluates visibility for the rest pose and each state of each group with the others at rest, without publishing the probe-only diagnostics (`look-with-closed-eyes`) a hypothetical selection raises. A layer whose visibility changes with a group belongs to it; a layer two groups both switch is an error. With several groups, whether one morph drives them or several, a layer whose own or ancestors' conditions name two or more driven groups is evaluated at every combination of those groups' states, and one that shows or hides at a combination other than its own group's state alone says (a drawing conditioned on one group inside another group's state layer, or on three groups at once) is a `mixed-groups` error naming every morph that drives one of those groups, since the player shows each group's leaves from that group's table alone. More than `MIXED_GROUP_COMBINATIONS` (4096) combinations for one layer is reported the same way rather than checked.
5. Splits paint order into runs of static and live leaves. Live leaves are the groups' state layers, every clip target and every drawing under a moved layer (below); a compositing ancestor (opacity below 1, a filter, a mask, a blend mode, isolation, whether from its attributes or its inline style) that holds both makes all of its leaves live, because splitting it would change how it composites. Art the author hid with `display: none` is no leaf, read from the inline declaration that takes effect (the last important one, else the last) or else the attribute. An inline style is read within a closed grammar (`svgDocument.ts`): names and values in ASCII, with space, tab and line breaks between tokens, declarations ended by `;`, each with an optional trailing `!important`. Each run becomes a part: a full SVG document with the root's sizing, every ancestor's transform and inherited style, and the transitive closure of the resources it references (gradients that inherit gradients, clip paths whose contents use patterns), its kept ancestors' own references included. A resource copied out of its place sits inside groups that repeat what its original ancestors passed down, so a `currentColor` stop keeps its color, and whatever those ancestors reference (a pattern under `<defs fill="url(#paint)">` needs `#paint`) is in the part's closure too. Ids are namespaced under the artifact's prefix and every supported reference is rewritten: `url(#…)` in attributes and inline styles, and `href`/`xlink:href`.
6. Pairs each segment's appearing and disappearing drawings by identical nonempty effective label (the nearest labelled ancestor's) with `pairShapes`, in root user space, so ancestor transforms are honoured. Each drawn element is a pairing unit; a labelled group's elements all carry its label. Unlabelled drawings never pair. A drawing whose effective label has a `partner` list, and whose geometry the bake reads, pairs by that list first wherever one pose of a segment draws it and the other does not (see Partners below).
7. Applies policy, resolved field by field from the nearest configured label up to the root: `blend = morph` runs the explicit `method`, falling back with a diagnostic when it fails; `fade`, `cut` and `scale` apply to paired and unpaired drawings alike; an unpaired drawing under `blend = morph` uses its `fallback`; `depth` chooses which drawing of a moving pair carries it (see `draw` under Playing an artifact). A drawing inside a clip target holds through the segment instead, so the moving aperture alone decides what shows.
8. Skips each clip entry none of whose `targets` labels the variant draws, at rest or in any state of a driven group: the entry forms no aperture there and reports neither `target-missing` nor `edge-missing`, and the rest of the set plays. Every later rule about clips concerns the entries that remain, whose target labels the artwork lacks each get a `target-missing` warning. Forms apertures from each remaining clip entry's `between` edges: the bend tracks of the paired drawings with those labels (two open lashes converging on one closed lash are two tracks and one aperture). `between` lists the labels the clip accepts, and a variant uses the ones its artwork draws, so one morph serves a portrait that labels both lashes `eyelash-right` and one that labels them `eyelash-top-right` and `eyelash-bottom-right`; distinct labels pair one to one, which is how an author keeps lashes from pairing across each other where nearest position would cross them. Edges that are not bend morphs, compound edges, a lone edge, three edges sharing tips, an edge inside its own target, a clip none of whose `between` labels the artwork draws, or edges that never move disable the morph for the variant with a diagnostic. Between the rest poses an edge's boundaries are the frame its track draws there, split in two at its tips (`BendTrack.edges`), so the aperture meets the lashes the player draws; at a rest pose they are the authored outline. An aperture that closes to nothing is valid. A closed aperture is its midline traced out and back, so an opening blended towards it closes onto the lashes' line rather than onto the chord between their tips. Every sample of an aperture is resampled to the same number of points along its outline, so a player blends neighbouring samples point by point. Beside each aperture table entry, `apertureEdges` holds, per sample and per loop, the frames the loop's two edges draw there, each as a closed polyline (a drawing in straight segments keeps its points; a curved one is sampled eight points per segment), in root space as the apertures are.
9. Wraps each clip target in a group masked by its entry's aperture, in both the live part and the rest render. The masked group undoes the transforms around the target and a group inside it redoes them (both written at full precision), so the mask is on an element whose space is root space, the apertures' own. The target's own clip paths and masks stay on it, so they intersect. The rest render is the variant's static render in its shown look, the rest pose, unchanged except for those wrappers and their masks. An aperture mask's path is the rest outline: the aperture at the end of a segment that reaches the rest pose, or where no segment does, because the rest state is one no keyframe names, the outline read off the rest pose's own drawing (see the rest outline of a rest no keyframe names, below). The outline is filled and stroked past it on each side by its clip entry's `spread` in screen pixels (`APERTURE_REACH`, 1, where the entry leaves it out) with a non-scaling stroke, at any size the picture is drawn. A `spread` of `0` strokes nothing, so the mask is the outline's area alone. A negative `spread` strokes the outline black by twice its amount, which pulls the opening inside its outline by that much, untrimmed, leaving a ring of whatever lies under the targets; the recipe and the artifact's `clipTargets` record a clip's `spread` only where it is not 1. The outline lies on the edges drawn around the opening, and a clip edge and a drawn edge that coincide are each antialiased against what lies beneath them, which leaves a one-pixel seam of the layer under the targets; the reach moves the mask's edge under the edges, which paint over the targets at rest as the still image draws them. Away from rest a player gives the aperture the same reach, clipped to where the moving edges draw (see playing an artifact below): moving edges taper toward the opening's corners, thinner there than the reach, and on art whose closed state paints beneath the open eyes the closed lashes lie under the targets, so an unclipped reach would show the targets past the edges. Closure is judged loop by loop, since one clip entry may hold several eyes: a rest loop whose area is at most 1% of the widest loop its entry opens to (an eye resting closed) is not stroked, and when some loops are closed the open ones are stroked by a second path. A non-scaling stroke in a mask is drawn through the space of the element the mask is on, which is why that element's space is root space: under any transform around the target, scaled, skewed or rotated, the reach is the same. A browser composes those matrices in single precision, which moves the target by about 2^-24 times the parent space's condition number times the size of the coordinates involved, translations included; where that could exceed a ten-thousandth of the apertures' extent, the aperture is a clip path in the parent's space, the aperture mapped into it, with no reach and no `spread`; where its entry's `spread` is not 1, the artwork gets a `spread-ignored` warning naming the clip. The path's paint is spelled out (opaque fill and stroke), since a mask's content inherits from the artwork root rather than from the masked drawing. Drawn inline, as the player draws a live portrait, the reach is one device pixel; drawn as an image (`rest` in a hover, preview or CSS mask), it is one pixel of the artwork's own size, scaled with the image. The mask's region is the bounds of the apertures and the rest outline, grown by their own size.

### Partners

A label's `partner` names, in priority order, the labels whose drawing its own drawings take in a pose that does not draw them. A source is a drawing of such a label that one pose of a segment shows, as itself or carried, and the other does not; its other pose is the end that does not show it. The first listed label the other pose draws, among the drawings of the same group, decides. The label's own name decides by pairing by name, as step 6 pairs (`pairShapes`, failures included); without its own name in the list a label never pairs by name. Another label decides by its drawing whose box centre, curves included, is nearest the source's, the first in paint order on a tie (the rule `drawingIn` applies to `depth` carriers). A drawing never splits, and several sources may take one partner drawing. A source whose other pose draws none of its labels keeps today's behaviour, its fallback or holding inside a clip target, with one `partner-missing` warning per bake whose message every variant shares.

The arrival frame is the source drawn in the partner drawing's shape: the partner's geometry in root space mapped into the source's own space, with the source's own paint, at the source's place in paint order. `depth` does not apply. The source's blend, resolved from its label as for any drawing, decides how it gets there: `morph` runs its `method` from the shape it leaves to the shape it reaches, as an ordinary `morph` transition between the nodes of those two drawings marked `partner`, drawn on the source itself (a carrier of it for a basic shape or a node another track draws on) and with no `paint` record, so it keeps its own paint unless a `paints` entry for its label at that pose recolours it; a method that fails, or a missing `method`, uses the fallback as for any pair. `fade` fades its own shape out while the arrival frame fades in, `cut` holds its own shape to the segment's end and then shows the arrival frame, and `scale` shrinks its own shape while the arrival frame grows from nothing, each with the arrival frame on a hidden carrier of the source where both shapes show. A source inside a clip target follows its partner rather than holding, so its target's aperture keeps clipping it.

The source is carried: it stays drawn as its arrival frame at the segment's end, while the group holds that pose and at the start of the next segment. A segment leaving a pose that carries a source treats it as a drawing of its own label leaving that pose in the shape it carries, and applies the same list: back to its own shape where the next pose draws it, onto the next pose's partner drawing, into a same-labelled drawing where its own name decides (paint blending between the two as a pair's does), or out by its fallback from the carried shape, or holding there inside a clip target, where it draws none. The variant's rest pose shows exactly the still, so it carries nothing: a segment arriving at the rest pose hides the arrival frame at its end, and a segment leaving it starts with the source hidden and moves it out of the arrival frame. A source entering from a pose that does not carry it does the same.

A segment records what carrying needs. `shapes` holds the path data, in the node's own user space, of each carrier that draws an arrival frame or a carried shape in that segment's `fade`, `cut`, `scale` or `hold` transitions; `carry.from` and `carry.to` hold the nodes the start and end poses show as carried shapes, with their path data.

Frames are sampled at `MORPH_BAKE_SAMPLES` (8) evenly spaced progress values, the geometry package's tuning point, and mapped into the moving element's own user space so a player sets its `d` directly. A segment that moves the same drawings back reuses the earlier segment's frames and apertures reversed; geometry lives in the artifact's `frames` and `apertures` tables and transitions point into them.

### Moved layers

The keyframes can move layers by label (`motion` in the recipe). For each label the bake finds the artwork's elements with that label, outside resources, keeping the outermost where one holds another, and skips those that draw nothing in this variant. A label the artwork does not have moves nothing there, without a diagnostic: a morph often moves a layer only some of its portraits draw (a mask's nose), and compilation already reports a label no candidate image draws. A moved element that draws any part of a clip's `between` edges or `targets` holds still with a `motion-ignored` warning: apertures are baked in root space from where the edges are drawn and cannot follow a browser transform. So does one holding drawn art that something outside it draws again by reference (a `<use>`, or a clip path, mask or pattern that uses it), in the same part or another, since the copy would not move with the wrapper; a gradient or other resource defined inside it and painted elsewhere does not count. The rest are made live, and in their live part the element's copy is wrapped in `<g data-morph-motion="label" style="transform-box:fill-box;transform-origin:50% 50%">`, outside any clip or carrier wrapping, so the element keeps its own `transform`, paint and resources and the wrapper adds the movement around it. Its leaves are contiguous in paint order and all live, so the element lies whole in one part. The rest render has no wrapper.

### The rest outline of a rest no keyframe names

A rest state the keyframes never name is reached by no segment, so the bake computes no geometry for it: no frames, no partners, no carriers. Its clips still need an outline, for the rest render and for every frame that holds the rest. The bake reads that outline off the rest pose's own drawing, one clip entry at a time:

- Each of the entry's edges that the rest pose draws is bent onto itself, so its tips are the drawing's own tips. Edges whose tips meet pair into openings by the rule a segment's edges follow (`buildApertures`).
- An edge with no facing edge is a closed opening. It adds no loop, and the targets around it are cut shut, as a closed keyframe cuts them. One entry can hold closed eyes beside open ones.
- An entry none of whose targets the rest pose draws needs no outline: nothing at rest is cut, and its edges are not read.
- Every contour of every target of the entry that the rest pose draws must overlap an edge of that entry that the rest pose also draws (their bounding boxes meet). Otherwise the rest has no opening for that part of the target. A path that draws both eyes as two contours therefore needs lids around each.
- The variant bakes static, with an error naming the clip and the rest pose, when the rest pose:
  - draws a target with a contour no edge of its entry surrounds, including a target drawn with none of the entry's edges at all, or a target whose geometry the bake cannot read, such as text or a shape sized in percentages (`edge-missing`);
  - draws an edge that does not morph with `bend` (`edge-not-bend`);
  - draws edges that share tips ambiguously or form no aperture (`aperture-ambiguous`, `aperture-unpaired`, `aperture-degenerate`).
- The outline's loops join the entry's mask region and its widest-loop figure, alongside the segments' apertures, so the mask always contains the outline.

## Playing an artifact

`render.ts` draws an artifact at any pose as one SVG and is the executable statement of these rules; a live player follows the same ones.

- Parts paint bottom to top and overlay exactly (they share the root's view box and sizing). Static parts never change.
- A live part's markup is the rest pose: leaves another state shows carry an inline `display: none`, so the parts composed as written match the rest render. A player shows and hides leaves through that inline declaration. Nothing outranks it: a live leaf carries no inline `display` or `display` attribute of its own (art the author hid is no leaf), and artwork carrying a style sheet is never baked live. At a keyframe, a group shows the leaves `visibility[group][state]` lists and hides its others; leaves outside every group are always drawn.
- Progress arrives already eased by the morph's timing; nothing here eases again. Within a segment, a frame blends its two nearest samples linearly, from the last sample backwards when the geometry reference is `reversed`.
- The artifact's `groups` names the morph that drives each group, and each group is posed at its own morph's offset: `morphPosesAt` takes one offset for every morph, or one offset per morph, and leaves a group whose morph has none at rest. The morphs of a set never share a group, a moved label or a clip, so posing one leaves the others' drawings as their own poses put them.
- At either end of a segment the authored drawings show as they are, never their sampled frames: the start pose is the `from` leaves' own geometry and the end pose the `to` leaves'. A live part writes every drawing exactly as authored (a path's `d` with its relative commands and arcs, a basic shape as the shape it is), so the parts draw what the rest render does; a basic shape that moves draws its frames on a carrier written as the equivalent `<path>`, so a player can set its `d`.
- `morph`: between the ends the `draw` leaf takes the blended geometry, and at the end the `to` leaf's own drawing takes over, so a destination several tracks share is drawn once. A moving drawing paints at the depth its layer has in the pose its `depth` names, in both directions, so its stacking holds for the whole morph: `draw` is whichever of `from` and `to` that pose shows. `depth` resolves field by field like the other policies, by the nearest configured label of the drawing that leaves; its default, `rest`, names the variant's rest pose, the pose the static image shows, so by default the live layer order always matches the still. A named state is one the keyframes name for a group the morph drives (`eyes.closed`), and the state the morph starts from stands for the variant's own resting choice, as it does in the keyframes. Where a named pose shows neither drawing (a segment of a multi-keyframe morph that does not reach it), `draw` is a carrier of that pose's drawing of the same label in the same group (one whose geometry the bake reads; the one whose box centre, curves included, is nearest `from`'s when it has several), so the stacking holds through every segment; the drawing itself may be held, fading or another pair's end in that segment, so it keeps its own role. Where it draws no such drawing, or names another group than the one the drawing changes with, the rest pose decides instead, and `draw` is `from` when the rest pose shows neither too; the default `rest` never looks past `from` and `to`. A label with moving drawings none of which the named pose places gets a `depth-ignored` warning; a one-sided drawing under it moves on no track and is not counted. One element carries one shape, so where several tracks draw on one drawing (two open lashes converging on the closed lash a variant rests on), the second and later tracks draw on carriers: hidden copies of that drawing written right after it in its part, with no ids, which no state shows. Every track of a basic shape draws on a carrier, written as the equivalent `<path>`, so the shape's own markup is never replaced. Paint follows the shape: where the two drawings' fill colour, stroke colour, `fill-opacity`, `stroke-opacity` or own `opacity` differ, or the drawing `draw` copies differs from them, the transition's `paint` records both ends' values of those properties, and between the ends `draw` is written with their blend at the segment's progress, inline and important where its markup's own declaration is, so a carrier never shows its source drawing's paint between poses. At the ends nothing is written and the authored drawings show as they are. Each drawing's value is its inline style (the last important declaration, else the last) or else its attribute, else what it inherits from its ancestors (all but `opacity`), with `currentColor` read through `color`, else the SVG initial value (black fill, no stroke, opacities 1). Paint is read within a closed grammar (`paint.ts`): a fill or stroke as a colour or `none`, `color` as a colour or `currentColor`, an opacity as a number or percentage, any of them as `inherit` or `initial`, with an optional trailing `!important`, in ASCII with space, tab and line breaks between tokens. When any declaration that decides a paint lies outside it (another CSS-wide keyword, `all`, `var()`, a comment, an escape, an XML character reference in an inline style, which the bake reads as written and a browser decodes, other whitespace, non-ASCII text), that paint is unknown and the pair stays unblended, as an unreadable paint does. Colours read as hex, `rgb()`, `rgba()`, `hsl()`, `hsla()`, a named colour or `transparent` (`color.ts`) and blend in gamma-encoded sRGB with premultiplied alpha; a `none` fill or stroke is the other end's colour at zero alpha, so paint present at one end only fades in or out. Opacities blend linearly. Gradients blend too (`gradient.ts`): where both ends fill or stroke with a bare `url(#id)` naming gradients of the same kind (linear or radial) with the same number of stops, the same `gradientUnits` and the same `spreadMethod`, and the drawing `draw` copies would not already show the same gradient at both ends, the transition's `gradients` records both ends, each resolved through its `href` chain (each attribute from the first gradient in the chain that sets it, coordinates only from gradients of the first one's kind, and the stops of the first that has any). Each node a gradient blends on gets its own copy of it (one for each way the gradients it carries are built: kind, units, spread and stop count), written unreferenced in the live part that draws the node, under the artifact's id prefix, so the authored drawing and other carriers keep theirs; between the ends `draw` paints with `url(#copy)` and the copy takes the blend: coordinates and stop offsets linearly, stop colours as solid paint blends (each stop's `stop-opacity` folded into its alpha), and `gradientTransform` entry by entry. A `userSpaceOnUse` gradient is placed in `draw`'s user space as its own drawing shows it, the map from that drawing's space folded into its transform; an `objectBoundingBox` gradient keeps its unit coordinates and follows the moving shape's box. The fill or stroke's opacity blends as a colour's does wherever both ends paint with matching gradients, a copy or not. A gradient is read within a closed grammar: no inline `style` or `transform` attribute on any gradient in the chain, nothing but `stop` elements in them, links of the form `#id` through `href` or `xlink:href` (its prefix bound to the XLink namespace) to other gradients, gradients and stops in the SVG namespace, `gradientUnits` and `spreadMethod` spelled exactly, coordinates and offsets as plain numbers or percentages no larger than 1e300 (a percentage in `userSpaceOnUse` only at zero, since any other resolves against a viewport), a `gradientTransform` of the six transform functions with plain numbers and matrix entries no larger either, stop colours in the paint grammar (an inline style on a stop declaring nothing but `stop-color`, `stop-opacity` and `color`), and nothing that may set `color-interpolation` on the gradients, their stops or their ancestors (the attribute, the property, `all`, or an inline style the paint grammar cannot split). A fill or stroke either end paints with anything else (a pattern, a gradient outside the grammar, a gradient against a colour, gradients that differ in kind, stop count, units or spread, or colour syntax the reader does not know) records neither it nor its opacity, and the shape keeps the paint of the node it draws on. Stroke width and the other stroke geometry, and what composites on an ancestor, stay with that node. `fade` multiplies the leaves' own opacity, read from the inline declaration that takes effect when they have one, since that outranks the attribute, and written back inline, important when that declaration was; `cut` holds `from` until the end; `scale` follows its frames on its `draw` leaf (the drawing itself, or a path carrier for a basic shape), is invisible at its zero endpoint and is the authored drawing at its full one; `hold` stays drawn.
- `paints`: the artifact's `paints` lists, in authored order, each entry that applies to the variant. An entry with a `when` applies where the variant's rest pose draws a layer that needs that state, through its own name or an ancestor's (a condition on the state's group that accepts only that state); one without applies wherever the morph plays. The bake reads a selection that picks the state but draws nothing that needs it as not applying. Where it applies, the entry's `nodes` are the drawings of its target labels (on the drawing or an ancestor) that the pose shows, among those that change with the pose's group and those no driven group switches (which the bake makes live so a frame can recolour them), and its `tracks` are the `morph` tracks of segments arriving at or leaving the pose whose end there is one of them, by the node each draws on, with the paint the track shows at its two ends without the entry (its `paint` record, else the paint its ends share). A drawing of a target label that a partner carries to the pose counts there as a drawing of its own label: its node joins `nodes` with its own paint, and the `partner` tracks carrying it to or from the pose join `tracks` with its own paint at both ends; an entry for the partner's labels leaves those tracks out. A target label the pose neither draws nor carries gets a `paint-target-missing` warning. While the group holds the pose, its target drawings take the entry's colour and opacity: a `fill`, `stroke` or `opacity` the entry sets replaces the drawing's own. In a segment arriving at the pose the colour moves in linearly over the segment's last `span`, with weight `w = clamp((p - (1 - span)) / span)` at segment progress `p`, mixed in sRGB over the paint each drawing shows without the entry (`none` is the entry's colour at zero alpha); an `opacity` mixes linearly over the drawing's own opacity, read as a moving drawing's paint is (its inline declaration that takes effect, else its attribute, else 1), and a track's base is the blend of its two ends' opacities, as for colours; a segment leaving the pose mirrors it. Where the drawing fades at the pose, the fade's factor multiplies the entry's opacity. Tracks take the mix on the node they draw on, and so do target drawings both poses show, a drawing no driven group switches among them, and a carried drawing wherever it shows, scaling in or out included; a pose drawing showing as itself (at the segment's end, fading, cut or scaling in or out) takes the colour. `span = 0` changes the colour only where the pose's own drawings show. A drawing or track whose own paint the bake cannot read takes the colour only at full weight. Drawings a frame hides are not written, inline and important where the markup's own declaration is, as blended paint is; a property the entry leaves out keeps the drawing's own paint. Where two entries recolour one drawing, the later wins. The rest render and the parts as written never carry an entry's colour, and a static artifact has none.
- Carried drawings (Partners, above): strictly between a segment's ends, a carrier the segment's `shapes` lists takes that path data wherever a transition shows it, unless a `morph` or `scale` frame already gives it geometry. At the segment's start and end every carrier `shapes` lists hides, and the nodes `carry.from` (at the start) or `carry.to` (at the end) lists show with their path data, in their own paint. A group holding a pose after a segment shows that segment's `carry.to` the same way, and a group holding the pose it starts from shows none.
- A drawing's `spread` (Spread, below) grows or shrinks its outline by that many screen pixels while it is not showing its own art.
- A clip entry's aperture in a segment is that segment's `apertures` entry, written into every aperture `clipTargets` lists for the entry; outside its segments an aperture keeps its last pose. Between two samples the aperture is their point-by-point blend at the precision path data is written with (`aperturePathData`). Each sample spaces its points along its own outline, so point k of two samples need not be the same place on the opening and the blend can cross itself; where it does, or passes through one of its own points, the part winding the way the wider sample does is kept, so the aperture drawn between two samples is a simple loop. A progress that falls on a sample draws that sample as stored. Strictly between a segment's ends a negative `spread` strokes the aperture black by twice its amount with no clip path, and `0` draws its area alone. An aperture with a positive `spread` written with anything but its rest outline keeps its reach, stroked by twice its `spread` and clipped by a clip path the mask holds (`poseAperture`) to the aperture and, around each loop still open, the drawings of its two edges, blended the same way from `apertureEdges` (`apertureReachPathData`). Those are the moving drawings the player draws, so the reach puts the targets under the edges' antialiased inner edges and nowhere the edges do not cover. That hides the reach only where the edges paint over the targets, so a segment's clip entry lists in `reach`, per aperture, the loops whose own two moving edges both have homes after every drawing of the aperture's target in paint order (a carrier paints right after its home). A loop is judged by its own edges alone, so one eye's lashes do not take the reach from another eye's targets in the same clip entry; a loop whose edges paint beneath the target, as under a named `depth` or on a variant resting closed whose closed lashes paint beneath the whites, keeps its area alone. The moving drawings are drawn strictly between a segment's ends; at either end the poses' own drawings take over, and a closed state's may paint beneath the targets, so the closed keyframe and a held state draw the aperture's area alone. The clip path's rule is spelled out (`clip-rule:nonzero`): a clip path's content inherits the artwork root's, which exported art often sets to `evenodd`, and the clip's loops overlap.

`morphFrameState` is these rules as data: for a pose of every driven group it lists the leaves that show and hide, the path data and paint a moving leaf takes, the values of each gradient copy it paints with, the factor a fading leaf's opacity is multiplied by, the spread each leaf takes and the path data of each spread mask, and the path data of each aperture and of where it may reach, and leaves everything else to the markup. `renderMorphFrame` and `renderMorphAt` draw it as one SVG, posing each leaf, gradient copy, spread mask and aperture path from its markup with `poseLeaf`, `poseGradient`, `poseSpreadMask` and `poseAperture`; the player rasterizes that markup into the poses it draws on a picture's canvas (see Playing in the web player), and a layered picture's canvas poses its `<image>` leaves with `poseLeaf` alone.

### Spread

A drawing's `spread` is resolved like the other `layers` policies, by the nearest label that sets it, else the root's, else `0`; a track (a pair, or a source moving to its partner) takes it from the drawing that leaves, and a one-sided drawing takes its own. It applies only where the drawing does not show its own art: strictly between a segment's ends on a `morph` or `scale` transition's `draw` leaf and on both leaves of a `fade`, and on a drawing carried in its partner's shape, wherever a segment's `shapes`, `carry.from` or `carry.to` shows it, at the segment's ends and while the pose holds. A transition records its `spread` and a segment's `spread` records it for each node it carries; the poses' own drawings, `cut`, `hold`, the rest pose and the rest render never take it, and a morph without a drawing `spread` writes none of these records, so its artifact is the one it bakes without the field.

The artifact's `spreads` lists each node that takes a spread in some frame, with its `outline`: the node's own drawing as path data with every subpath closed, since a fill closes each subpath and a stroke does not, so an outline closed only implicitly would take no spread along its closing edge. A shrinking node (a negative spread) has a `mask`, written unreferenced in the live part that draws it under the artifact's id prefix, as gradient copies are: one path holding that outline, filled white and stroked black by twice the amount with a round-joined, non-scaling stroke, its paint, `fill-rule:nonzero` and visibility spelled out, since a mask's content inherits from the artwork root. The mask's region is the default one around the node's own box, and nonzero covers whatever an even-odd fill draws, so where the node paints the mask is the node's own area less a band of the amount inside its outline. A frame shrinking the node writes `mask:url(#…)` on it and sets the mask's path data to the node's frame geometry, or to its `outline` where the frame gives the node none (a fading drawing's own shape), with every subpath closed, and the stroke's width to twice the amount. The black stroke runs along every edge of the path, so it shrinks the drawing only where every edge bounds its fill; along an edge with fill on both sides (contours that overlap, touch or repeat, or one contour folding over itself) it would cut a slit. A drawing therefore shrinks only when every outline it shows while its spread applies is a single contour that does not overlap itself with fill on both sides (below): an author who sees `spread-ignored` for a drawing of several contours draws each contour as a layer of its own. The artifact's `evenodd` marks a shrinking node filled even-odd, and a frame shrinking a node first tests its contour. The test is exact to a tolerance of a ten-thousandth of the drawing's size: the contour's curves are flattened until each piece lies within a quarter of the tolerance of its curve, its edges are split where they cross or run along each other (edges paired by a sweep over their bounds), and each piece is tested on both sides with that fill rule. A piece with fill on both sides counts where the region on its deeper side, wound past the winding of its shallower side, is wider than the tolerance, that is, where a circle as wide as the tolerance touching the piece fits in that region without crossing its boundary; a loop traced twice the same way, filled three deep inside, counts as any other overlap. A narrower region reads as touching: an end that overshoots its start by a sliver, a curve's loop thinner than the tolerance, or an edge drawn back along itself the opposite way (the same winding on both sides) shrinks, and the mask cuts along it as it cuts along edges that touch, a band of twice the amount however long the region is. The result is kept for path data a frame repeats, so an outline that does not change costs nothing after its first frame. On a frame whose contour has a piece with fill on both sides beside a wider region, which the stored frames cannot rule out for the frames interpolated between them, the frame writes no mask, and the drawing shows its own size for that frame.

A growing node (a positive spread) has a `grow` record of its own fill: a colour with its `fill-opacity`, or, for a gradient, an opaque copy of it (each stop's opacity set to 1) with the opacity its stops share. A frame growing the node sets its path data to its frame geometry, or to its `outline`, with every subpath closed, and strokes it twice the amount wide with a round-joined, non-scaling stroke in the paint its fill has in that frame: a `paints` entry's colour or the blended colour where the frame writes one, else the transition's gradient copy, made opaque in that frame, else its own fill from the `grow` record. Fill and stroke are written opaque with `fill-opacity` and `stroke-opacity` 1, and the fill's opacity (its colour's alpha, or its stops' shared opacity, times its `fill-opacity`) multiplies the node's own opacity, so the band and the fill composite once and a see-through fill shows no darker band where they overlap. A `paints` entry's `opacity` and a fade's factor compose with it as they do on any leaf.

A drawing keeps its own size, and the bake reports `spread-ignored` on the artwork once per label, as `depth-ignored` is reported, where the node drawn has no outline the bake reads exactly (text, an image, a reference, or a shape whose geometry it cannot read), where its stroke paints at either end of its move (any stroke other than `none`, read as paint is read, an unreadable one included, or a stroke a `paints` entry gives one of its drawings), where a positive spread meets a fill that cannot be grown (a pattern, a gradient whose stops differ in opacity, or paint outside the paint grammar, at either end or on the node drawn), where a positive spread meets a `polyline` (whose path data a frame cannot set, so its closing edge would take no band), where a negative spread meets a drawing with its own `mask`, or where a negative spread meets a drawing whose outlines shown while its spread applies (its own drawings at either end, a partner's shape it is carried in, and each stored frame of its `morph` or `scale`) are more than one contour, or one contour overlapping itself with fill on both sides by the same test. A label with a nonzero `spread` whose artwork draws it but never between poses or carried (only held or cut) is reported the same way. The clip edges' outlines, and so an aperture's reach, are their blended outlines whatever spread the edges take.

## Timing

A morph's timing and its layer movements' values are not in its recipe or artifact, so retiming or retuning bakes nothing again. A player schedules each occurrence with a `MorphTimeline` (`timeline.ts`): the first play starts after `delay`, each later one after a quiet gap drawn uniformly between `iteration_delay_min` and `iteration_delay_max` (none without bounds), and `iterations` counts the plays. The timeline answers where an occurrence is at a time: waiting for its first play (drawn at the offset that play starts from, its directed start before easing, 0 or 1, as a CSS animation fills backwards during its delay, so a one-shot does not show its end state first and a still can show the pose exactly), partway through a play, in a gap holding the end pose of the play before, done holding the terminal pose of a finite sequence, or off (`iterations = 0`). Each occurrence draws its gaps from its own seeded stream (`morphRandom`), so a seed reproduces a schedule and two occurrences never share one.

A speech morph's timeline (`trigger = speech`) starts no play on its own: the player hands it its character's speech with `speak`, as spans of time and, for a typed line, the beep times. With `sync = none` a play starts whenever none is in progress and the time lies inside a span, after the drawn gap. With `sync = beep` a play starts at each beep that finds no play in progress, a beep at the moment a play ends starting the next; with no beep times, as a voice clip's speech gives, its plays follow one another inside the spans. A play in progress always finishes.

A morph's `replay` block reaches the timeline as `timing.replay`, a list of ranges read by `readMorphReplay` (`morphSchema.ts`) with `from` and `to` as keyframe positions: a block of fields is one range, and a block of `{ … }` entries is one range per entry, in written order. The compiler leaves it out of the recipe, so adding or editing one bakes nothing and only changes the occurrence's `definition`. For each range the timeline finds once, through the easing (`morphReplayStretch`), the first moment of a play whose eased position is at or past `from` and the first at or past `to` (`to = 1` being the play's end); a stretch that takes no time replays nothing. Positions compare exactly; a `cubic-bezier()` peak that touches a position only to within floating-point rounding may or may not count as reaching it, while `linear()` and `steps()` stops stay exact.

A timeline with a range whose `chance` is below 1, or whose `delay_min` and `delay_max` differ, takes one value from the occurrence's stream when it is made, before any gap; any other timeline takes none. A morph with no `replay`, or whose ranges all have a `chance` of 1 and no `delay_min` and `delay_max`, draws exactly what it drew before, so its gaps and schedule for a seed are unchanged. A range that writes `delay_min` and `delay_max`, equal ones included, no longer takes a value for each replay, so the gaps after its plays come from other values of the stream than they used to. Each roll and pause is computed from that value, the play's number, the range's written position and the replay's number (`MorphTimeline.draw`), so any of them can be computed again whenever a frame needs it and a play keeps nothing for each replay. A range whose `chance` is 1 makes exactly `count` replays in every play. One whose `chance` is below 1 makes, from one computed value, as many replays as rolls of its `chance` made one by one would succeed before the first failure, at most `count`: the value is read through the geometric distribution those rolls follow, so the number of replays costs the same to find whatever `count` is. A replay's pause is drawn evenly between its range's `delay_min` and `delay_max`, and equal bounds draw nothing. A range whose `chance` is 0 draws nothing, so a list of one range draws exactly what the same fields written directly draw. The play's path then runs forward from 0. At the nearest turning moment ahead of the playhead belonging to a range with a replay left, the first range in written order with that turning moment and a replay left takes it: the path holds that range's keyframe position `to` for the pause and resumes from its `from`. A range's replays count over the whole play, so another range carrying the path back over a stretch gives it no more, a play makes at most the sum of its ranges' counts, and with no replay left at any range ahead the path runs to its end. Ranges may overlap, nest or repeat. The play's length is `duration` plus each replay's stretch and pause, and the next play's earliest start follows that length. A reversed play reads the whole forward path back to front.

The timeline takes a range only when its `count` is a whole number from 1 to `MORPH_REPLAY_COUNT_MAX` (1000), the bound the compiler checks; like `readMorphReplay`, it drops a range whose `count` is larger or not a whole number, so a timeline built directly holds the same ranges a compiled morph sends it. A path is kept as rounds rather than replays (`MorphTimeline.walk`). The turn after a turning point depends only on where the path resumes and which ranges still have replays, so once the path resumes where it resumed before with the same ranges left, the turns between repeat until one of those ranges runs out: the walk keeps that sequence once, with the number of times it repeats, and a play of any `count` holds a few rounds. Every time the timeline gives is the per-replay sum, found by visiting the path's steps in order from the play's start (`MorphTimeline.visit`): a frame's position takes each run and pause from the time elapsed in turn (`seek`); a speech turning moment is the play's start plus the first run, then each pause added together with the run after it (`settle`); and the play's length is `duration` plus each replay's pause and stretch in order (`length`). A turning moment or a play's end that lands exactly on a span's end therefore falls on the same side of it as when every replay was kept. A frame walks at most the sum of the ranges' counts, and the play keeps nothing for each replay.

A speech play settles each turning point, before its pause, when the timeline reaches it, by the test that lets a new play start (`MorphTimeline.spanFrom`): the speech goes on while some span ends after that moment. A turning point in the gap between two spans, as an unvoiced character leaves between words, is inside the speech: its replay holds the pose at `to` until the next span begins, as a new play waits for the next word, and begins at the later of that start and the end of its written pause, which still counts from the turning point. One after the last span has ended is outside the speech. A turning point inside a span holds for its written pause alone, so a play whose turning points all fall inside spans keeps its path unchanged. With `sync = beep` the test still reads the spans, not the beeps. The timeline settles turning points in order, each at its own turning moment, in one pass from the play's start up to the playhead (`MorphTimeline.settle`); a hold or a skip changes the path, and the pass starts again from where it stopped. A turning point inside a span needs no record. A hold in a gap is kept in a per-play map by the step's number, so a play keeps at most one hold for each gap in its speech. Going forward, a replay whose turning point lies outside the speech is skipped and spent, whichever range it belongs to. Every other replay due at that moment, of that range or of another range sharing the moment, is settled at the same moment and skipped too, so every range turning there spends all its replays left at once (`MorphTimeline.skip`), and the path runs on past it. Going backward, the play reads the forward path back to front, with every replay taken, until a turning point (where it reaches a range's `from` and would cut back up to its `to`) lies outside the speech. Every range turning back at that point spends all its replays left, and from there the play builds the rest of its path itself, through `walk` going down. It runs down past the skipped turning point, and at the nearest `from` below it whose range has a replay left, the first such range in written order cuts back up to its `to`, holds and runs down again. Each of those turning points is settled against the speech in the same way, and with no replay left the play runs to 0. A range's spent replays stay spent, so a skip never gives a range more replays than it drew.

A play's progress is directed (`reverse` and the `alternate` directions run some plays backwards) and then mapped once through the morph's `easing` (`easing.ts`, the CSS timing functions `easingProblem` accepts, `steps(3)` being `steps(3, end)`). The result is a keyframe offset, and `morphPosesAt` finds each group's segment at that offset and its progress within it: nothing eases a segment, a fade or an aperture again.

## Playing in the web player

The engine puts one play for each morph of a reference's set on the image write that shows its variant (`UIModule.getMorphContent`): the shared reference, the morph's name, its timing with its defaults, an identity of its definition (recipe and timing) and the image's place among the write's images, counted in the CSS it paints them with (`cssList.ts`), so a literal listing several images keeps the count. With the reference goes the morph's layer movement, when its keyframes move any layer: for each moved label, the property values written in the keyframes that set them, as CSS text (`buildMorphMotion`), with a property's rest value (`0px`, `0deg`, `1`, `none`, `50% 50%`, `1`) added at offset 0 or 1 where its first or last setting is not there. The definition identity covers it. A write carries references, never artifacts, so it stays small and its JSON deduplicates as before; a write with no morph on its images carries nothing new. A reference with no asset service behind it (inline art, as VS Code and local compiles carry it) names art only the program holds, so the game bakes it with `inlineMorphSource` and sends the page the artifact once per key and connection (`morph/artifact`, plain JSON as an asset service's response is). An image whose morphs overlap has a reference per morph; it stays still, and the game warns once, naming the morphs and what each overlapping pair shares, since each artifact draws the whole image and declaration order is not the author's choice of which one plays.

The page's `MorphPlayback` (`spark-web-player/src/app/morph/`) belongs to the overlay and outlives the UI managers a re-render swaps in. For each written background layer it resolves the references through its host (the asset service named by `ref.src`, as the web editor's service worker is, or the artifact the game sent) and draws the layer in a shadow root over the span: each image in paint order, a vector picture the write lists in `pictures` on a canvas (see Pictures made of image files, below, for both kinds of canvas), placed on the rectangle CSS would have drawn it in (`backgroundFit.ts`), from the span's fractional padding box and snapped to device pixels as the browser snaps a background image, and every other image as a CSS background with the layer's own size, position and repeat. The placement is taken again when the span resizes and after every screen op, since a style or class change can move the image without resizing the span. While a reference is pending, and for good if it fails, a vector picture shows its rest on its canvas. A morph on an image the write lists no picture for, which only a picture with a layer that is not an image file gives, draws nothing there: the previews show the placeholder, reason `unlisted`, and the game warns once through `morph/still`. No picture is drawn as inline SVG. A mask layer plays no morph: it shows its pictures' outlines (`MorphGroup.outlineOf`) and never moves.

The plays that share an image share its reference, its artifact and its drawing; each keeps an occurrence of its own. Every frame poses each group at the offset of the morph that drives it, so each morph's shapes, apertures and moved layers follow that morph's clock. A morph in a gap between plays, or done after its last, holds the pose its play ended on (see Timing), one waiting for its first play shows the pose that play starts from, and one off leaves its groups in the rest the artifact's `rests` names for each group, while the others move.

A morph's phase belongs to its logical occurrence, not to the span drawing it: the target and content element, the image's place in the composition, the character, the morph and its definition, and the engine's epoch, which loads, restarts and resets advance. A compatible write (another expression of the same character) or a reconciling re-render draws the same occurrence at the same phase; the outgoing layer of a crossfade freezes on its last frame until its fade ends and is then released with its artifact references. A different character, an edited definition, a new epoch, a new PLAY session and previewing another place start occurrences again at rest. Phase is never saved.

A label the play moves is moved by one Web Animations effect with the label's keyframes, a duration of 1000 and `fill: both`, on an animation attached to the document's timeline that is never played (`browserAnimator`): it is created idle and its `currentTime` is set to the eased offset the shapes and apertures are drawn at, so the browser interpolates the CSS (lists of different functions, percentages of the wrapper's fill box, the individual properties' order) while the morph's clock alone moves it. A drawn portrait's pose commits that effect into the pose's markup when the pose is drawn (`movedMarkup`), and a layered picture's canvas reads it back from a stand-in each frame; a rest frame cancels it, and so does disposing the layer. An animation with no timeline would also never run, but Chromium draws such an animation only at the first time it is given and keeps that frame after later seeks. Without Web Animations a moved layer stays where it is drawn. During PLAY the application's clock drives playback, so pausing the story freezes every morph on its exact frame. A stopped preview never starts that clock; playback runs on animation frames of its own instead, which advance nothing in the story. The `Animate portraits` preference (`game/setAnimatePortraits`) returns every morph to rest and keeps it there, paused or not; turning it on starts each one on a fresh cycle. It holds for artifacts still pending too. `MorphPlayback.preempt` holds an occurrence at rest until released and then resumes its schedule where it stopped, the seam a later explicit transient behavior takes a portrait over by.

## Pictures made of image files

A `layered_image` (a portrait folder, a picture with layer files beside it, or one written in the script) gets references by the same binding as an SVG image: `buildMorphChannel` reads its candidates and `playingMembers` binds a look the compile did not list. Its artwork is built from its layer list (`layered.ts`, `layeredMorphArtwork`): one `<image>` per layer file in stacking order, named in `data-name` by the layer's own words and numbered in `data-layer`, nested in a `<g>` for each parent the vocabulary records, each covering the whole picture. A layer drawn through a `filtered_image` is sized, and its problems placed, by the image file under it. The picture's rectangle is its bottom file's pixel size, which the host reads from the file's header bytes (`imageSizeOf`). A file is read only by the format its first bytes name. A JPEG or PNG that carries an Exif block before its image data (a JPEG APP1 `Exif` segment before its scan, a PNG `eXIf` chunk before `IDAT`) has no size, since its orientation can turn the picture the browser draws, and so does a file whose read ends before that is settled: a JPEG whose walk meets stray bytes, a cut segment or the end of the bytes read before its scan, or a PNG whose image data starts past them. A hierarchical JPEG frame (SOF5 to SOF7, SOF13 to SOF15), which the browser does not decode, has no size; a GIF is as large as its first frame reaches; a BMP with a 12-byte core header has 16-bit sides; a WebP is read from its first chunk. A file that carries Exif data is therefore not checked; re-exporting it without metadata restores the check) and the workspace carries on the file as `width` and `height` (`SparkdownWorkspace.readImageSize`, which asks the host through the `sparkdown.getFileImageSize` command; SVG files get no size). A file the host lists at start-up without a size is asked about only once start-up is over (`loadImageSizes`, from the language server's `initialized` and after the player workspace's initialize), since a VS Code client answers no request from the server while it initializes; each size that arrives updates the compiler's copy of the file and the program compiles again. The artwork's root then carries that `viewBox`, `width` and `height`; where the host gave the bottom file no size, it is the `0 0 100 100` rectangle with no `width` or `height`. When the bottom file and another layer file both have a size and they differ, the picture has no artwork (`layeredSizeMismatches`), so it gets no references and is drawn as a still. For each such picture a morph fits, the compiler warns on each file of another size, naming both sizes, the picture and its bottom file (`layeredSizeWarnings`). It is built from the current context each time it is asked for, since a layer can depend on images the picture does not name (a `filtered_image` layer's underlying file). The artwork needs no fetch, so every host bakes it in process (`layeredMorphSource`, which `inlineMorphSource` falls back to), and a reference carries no `src`. It carries `layered: true` instead, and every reader of artwork (the engine's and the language server's) reads a reference so marked from the picture's layer list, since an image file may share the picture's name: a hand-written `layered_image` named `kit` may use the file `kit.png` as its base. References listed under a name belong to the image that name resolves to; a struct that resolves to another image of that name (the base file inside the picture) gets its own, by the binding rule. The key's artwork token is a hash of that text and every layer file's source token, so it covers the bake format, every layer's name and source in stacking order, the selection and the recipes. A layer that resolves to more than one file, such as a nested `layered_image`, leaves the picture without artwork and without references. The language server bakes it for diagnostics and reports each on the layer file its `path` names (`paths` maps an artwork node's path to its file), else on the picture's bottom file; it gives a layered picture no rest render, so a hover shows the rest look through its layer list (`shownImageLayers`).

One resolver decides an image's look (`look.ts`, `resolvePictureLook`), and every caller reads it rather than resolving a look or a pick from the image's visible layers: the engine's image write (its background, sources and morph plays), `getBackgroundImageFromString`, `getImageAssets`, `imagePick` and `createImage`; the language server's hover preview, the Variants tester and the `morph` clause's completion; and the compiler's look scan and `morph` clause check. Given the context, the channel, the image, the directive's pick (a name, or a function deciding each layer) and optionally the start pose, it returns the picture's root, its pick, its references, whether the picture's own morph plays, its visible layers with each one's pick and references, the rest and start looks, whether the look is empty, every pick it decided and the speech morphs that play on it. A picture gets one reference for the whole picture, where `getMorphContent` gives an SVG image one for each CSS layer, and it plays only when it is the only one and the picture has artwork. The resolver also gives each file of the picture's artwork its own pick and references (`files`), so a layer hidden at rest counts too: an SVG layer with references of its own keeps them while the picture's morph plays, and a morph that fits both plays once at each level. Two references at the picture's level are a conflict (`conflict` is `overlap`): the game warns, nothing plays on the picture, and its visible layers still play their own references. A picture without artwork leaves its layers to play their own references. Where the picture's morph plays, the rest look applies its rest to the picture's own selection and resolves its layer list again, extending a `filtered_image`'s own attributes so a look the context does not hold (the Variants tester's) resolves too, and then poses each layer of that list by its own references; otherwise each visible layer is posed by its own references. The picture itself takes part in the pick as well as its visible layers, since a picture of overlays can show none at rest. Its speech morphs are those of the picture's own morphs that, picked, play on the whole picture, and its layers' own: every artwork file's where the picture's morph plays, else its visible layers'. The compiler reads a layered picture whose own morph does not play in its written look for its attribute diagnostics, as the picture is shown, never posed by that morph's rest. A preview shows the shown look: an empty one previews as empty, never as the look without the morph's rest. The engine resolves each image once per write, keyed by image and pick (a pick function by its identity, and the write asks `imagePick` once per image), from a cache that lives for that write only and closes even when the write throws (`UIModule.withPictureLooks`).

The image write's play for a layered picture carries `picture`: `span`, the count of CSS layers the picture paints, from its first layer, and `files`, every layer file's `src` and file name by `data-layer`, since the CSS holds only the layers shown at rest. Every image's CSS layers are counted from the background the write paints, with the directive's pick, since a speech morph's rest can change how many layers a picture paints. A named image whose look shows no layer paints `none`, never the look without the pick.

The player composites a layered picture on a canvas in place of its span of CSS layers. Its artifact's parts are read as text (`layeredMorphModel`); each frame poses every `<image>` and its ancestors with `poseLeaf` and draws the shown layers in order with their combined opacity (`layeredMorphDrawn`), which also lists the labels of the movement wrappers (`data-morph-motion`) around each layer, outermost first. The browser still interprets a moved label's keyframes: for each label the canvas keeps a hidden stand-in `<div>` the size of the picture in its own pixels, runs the label's Web Animations effect on it (one effect per label, sampled at the play's offset and cancelled at rest), and reads the pose back from its computed `translate`, `rotate`, `scale`, `transform`, `transform-origin` and `opacity` (`motionPose.ts`). The stand-in's box is the picture's rectangle, so `px` are the picture's pixels and a percentage or origin is of the whole picture. A layer is drawn with the product of its labels' poses, scaled from the picture's pixels to the canvas. A wrapper's opacity fades what it holds as one: a wrapper that holds several drawn files and is faded is drawn on a canvas of its own and composited once at that opacity, as the browser fades a group, while a wrapper holding one file multiplies its opacity into that file's; a layer moved past the picture's edge is cut off at the canvas. The canvas is redrawn only when that list, a pose or the canvas size changes. A file that carries plays of its own (an SVG layer with references of its own) is drawn on the same canvas, in its place in the stack, with its labels' poses and fades like any other file: once its artifact is live, the canvas draws it from poses drawn before the beat fires (`FileState.poses`, planned, budgeted and awaited as a drawn portrait's poses are, below), at the canvas's backing size and a beat's next one, in place of its rest raster; a pose change repaints the canvas. An SVG layer file (`pictureFileTraits` marks a file whose text begins with `<` as `svg`) is drawn on the canvas like a raster file, from a raster of itself that the browser fits as CSS fits the span's layer (`svgLayerFile.ts`): the player parses the file, sets its root's `width` and `height` attributes, and its CSS `width` and `height` with `!important` through the root's parsed `style` declaration (the root may set its own CSS `width` and `height`, which would otherwise override the attributes), to the raster's size, checks the copy it will rasterize against the same root rule as the file, since the rewritten attributes can bring other selectors into play, and refuses that raster when it fails (a raster refused at a later size stops the picture's morph with the `undrawn` warning, since the earlier raster no longer fits, and the picture is drawn as its still is, below), adds a `viewBox` of its natural size with `preserveAspectRatio="none"` only when it has none, and decodes and draws that copy once, first at the picture's size before the first draw and then at the canvas's backing size whenever that changes, one decode at a time per file for the latest size, keeping the previous raster until the next has decoded and releasing it when it is replaced or the picture is disposed; so it is registered with the raster layers in every engine at every device pixel ratio; the placed picture clips everything it holds at its rectangle, and a file's own plays pose it on their own occurrences, so a hidden layer keeps its place in its cycle. Until its artifact is live, the file is drawn from its rest raster. Where the picture's canvas cannot be drawn (its artifact failed or is not live, a file broke the canvas, or the canvas cannot be made), such a file's morphs hold still with the picture, which is drawn as its still is (below): at rest on its still canvas, or as the placeholder when that cannot be drawn either. Before the first draw, every file the parts name and the bottom file are loaded and decoded (`MorphLayer.prepare`), and the still shows until then. The picture's rectangle is the artifact's `width` and `height` when it has them, else the bottom file's natural size, placed where CSS places the span's bottom layer and snapped to device pixels, with a backing store at device pixels capped at 4096 × 4096. A picture's morph does not play, and a picture of image files keeps its CSS drawing while a vector picture is drawn as its still is (below), when a file fails to decode (a file whose `decode()` is refused still loads when it has loaded with a natural size and paints at least one pixel when drawn at its own size on a probe canvas (capped like the picture canvas and read in bands), since Chromium refuses `decode()` for large images once its decode budget is spent; a corrupt file that reports a size from its header paints nothing and is refused; a file whose bytes end before the image does, a PNG whose chunks do not reach `IEND` after image data, a GIF without its trailer, a WebP shorter than its RIFF length or a JPEG without an end marker after its last scan, is refused even when the browser decodes it, `pictureFileComplete`), when a file's natural size differs from that rectangle, or when a file is animated, carries a colour profile wider than sRGB or cannot be read (`pictureFileTraits.ts`, reading APNG, GIF, WebP and JPEG headers; a colour profile counts as sRGB when its red, green and blue primaries match sRGB's within 0.01, a grey profile is within sRGB, a profile without primaries and an `iCCP` the player cannot inflate count against it, and a PNG `cHRM` chunk is judged the same way when no profile overrides it; a `data:` URL is read in place, anything else through `fetch`); for those three the player sends `morph/still` and the game warns once, naming the file. An SVG layer file keeps the picture's morph from playing, with the same warning, when it does not parse as an SVG, when it animates (a SMIL `animate`, `animateMotion`, `animateTransform`, `animateColor` or `set` element, or a CSS declaration that names an animation, read by the browser's own CSS parser from each `<style>` and `style` attribute), when any declaration that applies to its root, from its `style` attribute or from a style sheet rule whose selector matches it as the browser's own parser reads them (every `style` element in any namespace; a nested rule or declaration block resolved against its parent's selector, `&` read as `:is(parent)` where it is a selector token, not inside a string; an `@import`, read by the browser's parser in an inert document since `replaceSync` drops imports, an `xml-stylesheet` instruction or a `link` element refuses the file), is not on the allow-list `ROOT_PROPERTIES` in `svgLayerFile.ts` (`width`, `height` and the SVG presentation properties that cannot change the root's box: the fill and stroke properties, `opacity`, `color`, `clip-rule`, `paint-order`, the rendering hints, `color-interpolation`, and the stop, flood and lighting colours; the warning names the declaration, reason `styled`; a style sheet the player cannot read refuses the file too), when it has no `viewBox` and its `width` and `height` are not both positive absolute lengths of at most 100000 (a number with an optional `px`, `in`, `cm`, `mm`, `Q`, `pt`, `pc`, `em`, `ex` or `rem`) or the browser's natural size for the file differs by more than a pixel from those lengths, or when the browser will not draw its copy at the picture's size. Every caller awaits one decode per artifact (`ImageState.loading`), so a group update while files decode commits the picture once they resolve. A layered picture used as a mask keeps the CSS mask, its rest look, and does not move.

A picture no morph plays on is drawn on a still canvas (`MorphLayer.startStills`) from the image write's `pictures`: a layered picture of image files, and a vector picture, one the engine marks `vector` because one of its files is an SVG (a single SVG file is a picture of one layer, an SVG drawn through a `filtered_image` counts, and a layer that is an image file drawn through a `filtered_image` is drawn on the canvas as the file under it). Each SVG file of a vector picture is drawn from a raster of itself that `browserSvgLayerRasterizer` fits at the size of the layer's tile on the canvas, and the canvas is painted only once every such raster has decoded at its wanted size, so the picture never shows half drawn. A vector picture keeps its CSS drawing only when a file animates itself or a bitmap layer is animated or carries a wider colour profile, as a layered picture of image files does; every other reason it cannot be drawn (a file that does not load or parse, `unsized`, `styled`, layer files of different sizes, a placement the canvas cannot follow, or a raster the browser refuses) leaves its CSS layers empty and, where the host turns `placeholders` on (both previews), a placeholder in the shadow root naming the picture and the reason, reported once through `morph/still` with `placeholder: true`. A vector picture a morph plays on is drawn at rest on a canvas of its own too (`StillPicture.unders`, the morph images that cover it: one covering the whole picture, or one or more each playing on one of its layers). Where each of those plays on one SVG layer of the picture and its artifact is live (a drawn portrait, a picture of one SVG file, or a morph on one layer of a multi-layer vector picture, `MorphLayer.posed`), that rest canvas is the picture's drawing from its first frame, and the morphs play on it from poses drawn before the beat fires (`ImageState.poses`): each frame, the playheads give each play's offset, the pose is the one drawn for those offsets, and the canvas is painted with that pose's raster in place of its layer's rest raster, the picture's other layers drawn with it as at rest, so no vector shape is rasterised after the beat fires. The poses are planned for each size the rest raster is wanted at, the shown one and a beat's next one (`planPoses`), as every combination of each play's options: at rest, and either every distinct state of a cut morph (a morph whose groups' segments only cut or hold, with no clips, `paints` entries or layer motion; sampled at each segment and schedule boundary and between them, `cutOffsets`) or the offsets `k / N` of a tween's grid, `N` being the count of a `steps` easing (`morphEasingJumps`) or the play's duration times `MorphPlayback.frameRate` (`morph_frame_rate`, sent in `assets/configure`; `0` holds tweens at rest). A tween's offset is rounded to its grid as it plays; a cut morph's is used as it is. Two options showing the same frame state (`morphFrameState`, compared with unit opacities left out, plus each moved label's offset, an offset of 1 counting as 0 when the label's track ends where it starts) share one raster, and one showing the rest frame shows the rest raster. Each pose's markup is `renderMorphAt`; for a pose that moves labels, the player puts that markup in a hidden stage in the page at the picture's own size, drops the markup's scripts, embedded documents (`iframe`, `object`, `embed`), event handler attributes and `javascript:` links, runs each moved label's Web Animations effect on its wrapper at the pose's offset (`MorphPlayback.animate`), commits the effect's values as the wrapper's inline style and reads the markup back (`movedMarkup`), so the browser interpolates every movement, transform lists and percentages of the layer's box included. Each pose is rasterised one at a time through `rasterizeSvgLayer` at the rest raster's size; a pose the browser will not draw leaves the rest pose in its place and is reported once through `morph/still` with reason `undrawn`. Planning is bounded before any pose is listed: a pose takes four bytes a pixel, against `frameBudget`, what `predict_cache_size` leaves (`AssetCache.predictionRoom`) less the poses every layer already holds, and a picture plans at most `MAX_POSE_FRAMES` (256) poses from at most `MAX_POSE_COMBINATIONS` (1024) combinations of its plays' options, counted from each play's option count and its distinct looks before any is listed; a tween's grid never exceeds 256 points, whatever `morph_frame_rate` or its `steps` count. The room limits only the poses tweens add; cut poses are planned whatever the room. Tweens are shrunk together to the largest grids that fit, a tween with no room holding the rest pose, and when the cut plays alone exceed either cap, the last of them in the image's play order hold the rest pose too (grid 0) until the rest fit. The beat waits for the artifact to settle and for every planned pose (`posesDrawn`). A drawn portrait whose rest cannot be drawn shows the placeholder, and one whose file animates itself keeps its CSS drawing; in both its morph holds still. A change morph that turns back (`ImageState.turned`) takes the frame its drawing starts from as the one its rest raster shows. When the morph cannot draw the picture, the rest canvas stays in its place, drawn, or as the placeholder when it cannot be drawn either, and the morph's warnings wait for it: a placeholder is the picture's one warning, and otherwise the morph's warnings are sent. A file of the picture that plays morphs of its own holds still with the picture in the same way. The canvas's backing size is the picture's box at the device pixel ratio times its reach: the largest framing zoom it is placed or travels at, the scale its element's transforms apply when it is first drawn (its bounding box over its layout box, less the framing's zoom), and the largest plain `scale` the beat's animations give it or an element that holds it (`keyframesScale`); a picture of image files only is never drawn above its files' own pixels, and no canvas exceeds `MAX_CANVAS_PIXELS`. Once painted, a canvas changes its backing only when a beat's measurement asks for it (`MorphLayer.prepareLayout`), or `SETTLE_MS` after its box last changed size; until then it is stretched, and a later move of its framing repaints nothing. A painted canvas keeps its pixels until every raster for its new backing has decoded, and then resizes and paints in one step.

The player fires a beat only once every canvas it shows is painted (`UIManager.prepareDrawing`). Before the beat applies, the player measures it once, as it will be applied: it copies the overlay beside it (`replicate`; the copy is hidden, inert and out of the accessibility tree, carries each element's written state, scroll position and resting framing, and loads no media), applies the beat's operations to the copy with the player's own handlers (`BeatRehearsal`, a `UIManager` with its engine replies, media, cutscenes, speech, document theme and drawing switched off and its morph mounts recorded), and measures each picture there. A picture's zoom reach is its framing at rest and at both ends of every move the beat starts or schedules (`pictureZoomReach`), and its scale is the product, over the picture and each element that holds it, of the largest scale the keyframes of each animation the copy runs on it give (`keyframesScale`; a move's own animation counts in its zoom instead). The copy's animations and transitions are then cancelled and its moves ended, so it shows the layout the beat leaves, and a picture under an element hidden by `display: none` is measured as if shown. Each shown vector still and each shown layered morph canvas is measured on its copy (`MorphLayer.prepareLayout` with a `PictureGauge`): one whose box keeps its size but needs a larger drawing is drawn again in place before the beat fires; one whose box changes rasterizes its picture at the new box beside its current rasters and adopts them and paints as the beat applies (`MorphPlayback.adoptPrepared`), keeping its drawing until then; a new-size raster the browser refuses gives the picture its placeholder and warning as the beat applies. Each picture the beat mounts is mounted held (`MorphLayer.hold`) on the span the copy made for it, so it is laid out where the beat lays it out, its layer's own sizing of its image files included, and a `change` morph starts only when the beat applies (`release`, which also re-reads the continuation from the layer it replaces). The copy stays beside the overlay until the beat applies; the write then takes each prepared span into its content element in place of a new one, and the layer keeps the box it had in the copy as its fallback (`MorphLayer.holdArea`). Nothing in the shown overlay is changed to measure a beat or while it waits, so its animations, transitions, focus, scroll positions, media and CSS layers are left as they are. Only a beat that cannot be applied to the copy (one of its operations throws there) applies with each created element that holds an undrawn picture hidden, its `ready` and `fired` marks landing when those pictures are drawn and shown (`veilMade`). A move with a delay changes the picture's box when it starts, after the beat has fired, and that box is not prepared; the move's zoom counts in the picture's reach.5 to 7 ms for the piecewise measurement it replaced. A beat that arrives while an earlier beat waits for its drawing, or while that beat's created elements are hidden, waits behind it (`drainWaiting`); a UI message outside a beat that arrives then applies the waiting beat at once and marks its undrawn pictures late. A layer not drawn when `beat_timeout` (play) or `restore_timeout` (the stopped preview), sent with the assets configuration, runs out is marked `late`: its pictures, a rest canvas under a morph included, show the placeholder, reason `late`, until their drawing lands, a morph canvas not yet drawn keeps its still picture and warns that it was drawn late, and a picture is reported once whatever reasons follow.

Every raster of an SVG file or a pose goes through one pool of drawings (`MorphPlayback.raster`), keyed by the raster's size, the file's natural size and the file (its parsed source, so two pictures of one file at one size share a drawing) or, for a pose, its markup. A drawing is made once and handed to every layer that asks for it at that size; it is released when its last user lets it go, unless the latest drawing ahead listed it. Drawing ahead starts when the engine sends `assets/draw` (`AssetModule.onBeatSettled`), once the current beat's text has finished typing or a click has shown it whole. The engine walks the scene table's beats ahead of the current one, as many as reach `predict_distance` beats that load anything, counting in play only beats the current line can reach (in the stopped preview, that many on either side of the cursor); in play, when the scene ends first and `predict_distance` is not `0`, the walk goes on into each next scene a `load` has loaded (`AssetModule.loadedSuccessorRoutes`, through a scene's `load` targets and diverts, only into loaded scenes, never into a scene twice on one route), up to that scene's first `load_distance` beats that load anything; each route through those scenes is walked on its own with the horizon it has left, after the current scene's beats, and the pictures of all routes are merged as the arms of a choice are, and follows each target's pictures from the write that shows them to the write that replaces or hides them (`pictureRuns`, seeded with what each target shows now). The scene table lists each image write of a beat (`SceneBeat.writes`: its target, pictures, `hide`, `animate`, `at`, `to` and `with`) and the blocks the beat sits in (`SceneBeat.scope`, one pair per enclosing block: the statement that decides between blocks, a choice or an `if`, and the block taken, so the arms of one decision share its first number and differ in the second, a later decision has another first number, and the beat where the arms join has their common scope). A write applies to the pictures shown in its own scope, in the scopes around it and in those inside it: a show replaces only the pictures shown in its scope or inside it, so a picture shown in one branch stays open beside another branch's, and a move after the branches join reaches both; an `animate` that names pictures adds them beside what is shown rather than replacing it; a hide grows the pictures it reaches by its effect and closes the pictures shown in its scope or inside it. Two scopes exclude each other only where they take different arms of the same decision; in play, a beat in another arm of a decision the current line sits in is skipped, and a later decision stays reachable. Each picture not on screen now that draws on a canvas is sent with its distance in beats, its content as a show write would carry it, and its reach: the largest framing zoom of its writes (`at`, and `to` of a move) and the largest scale its writes' effects give it, composed as a beat's preparation composes it: the scale keyframes of the picture's enter animation times those of its target's animations times those of each element a transition moves with it, as the image writer resolves `with` and a transition's `on_show` (`Image.effectScale`). A beat that only moves or hides a picture is listed for its writes and does not count against `predict_distance`. The player (`DrawAhead`) waits until no finite animation runs under the overlay (a letter's reveal, a move or a transition; one that repeats for ever does not count), then, nearest first, mounts each picture hidden in its target's image and mask content elements, measured in place before it starts drawing (`MorphLayer.presize`), with the reach it was sent, and waits for it to be drawn, or for the beat or preview timeout, before putting it away. A layer drawn ahead reports nothing; its drawings stay in the pool. A picture an earlier drawing ahead finished, at the same reach and with its target's elements at the same sizes and pixel ratio, is not mounted again while every drawing it asked for is still in the pool, a drawing refused for room included; those drawings take its new distance (`MorphPlayback.retain`). A beat, a UI message that makes, removes or moves elements or writes a picture, a click or a key stops drawing ahead; a style update, an animation, a presence change or a text write outside a beat puts away the picture being drawn and draws it again once nothing finite moves (`DrawAhead.interrupt`); a target whose element is not laid out is left to its beat. When a beat shows a picture the latest drawing ahead listed, its layer takes the listed reach as well as its own (`DrawAhead.reachOf`), so it asks for the drawing made ahead, and a later beat that zooms no further than that reach draws nothing. Each drawing and each outline records its holders (`Holders`): every request for it returns a handle that holds it for a shown layer or for a layer drawn ahead, and the handle releases it once, a second release doing nothing. A drawing or outline is idle when nothing holds it, and counts against `frameBudget` (what `predict_cache_size` leaves), at four bytes a pixel, while no shown layer holds it; one a shown layer holds does not count and is never dropped, and one any layer holds is never dropped. A shadow outline made ahead (`MorphPlayback.outline` from a mask layer drawn ahead) counts the same way at its width times height times four bytes, while the layer drawn ahead still holds it as well as after, is made only when it fits by the same rule as a drawing made ahead (otherwise it is not drawn or encoded, and nothing else is dropped for it), and is kept for a later list, dropped and released with the drawings; other idle outlines keep the outline cache's own limit of eight. A drawing or outline refused for room is remembered with its size (at most 256), and a picture is mounted again for it only once it would fit. A drawing made ahead that would not fit first drops the idle drawings the latest list no longer names, then the idle ones furthest ahead, and is not made when only nearer or equally near drawings would have to go; a drawing a shown layer asks for drops idle ones until it fits; and the pool drops idle drawings beyond the budget whenever a list starts or ends or a picture is kept. Pose planning counts only the poses shown layers hold, so a portrait plans the same frames ahead as in its beat and takes them from the pool. When a drawing ahead finishes, the idle drawings and outlines it did not list are released, and disposing the player releases every idle drawing and every idle outline made ahead.

## Diagnostics

A bake reports what it could not do as `MorphBakeDiagnostic`s with the morphs, layer and element they concern: the morph whose group, clip, `paints` entry or moved label a problem is about, the morphs whose groups a `mixed-groups` layer depends on, and every morph of the set for a problem with the artwork as a whole. Their `uri` and `variant` name the consumer the bake ran for. Several consumers can share one artifact key (the same art in two files, two names for one selection), so the language server bakes each key once and publishes its diagnostics on every artwork whose reference has that key, through the existing asset diagnostic delivery and merged with the compile's own. A change morph's pair exists only at run time, so it is checked when it plays. The player passes each change reference it resolves, with its artifact, to the current run's run-time diagnostics (`RuntimeDiagnosticsRun.addChangeBake`), keyed by the reference's key, so the same pair resolved again replaces its entry, and a later run of the same compiled program keeps them. The run sends them in `sparkdown/runtimeDiagnostics` as `morphBakes`: each entry's image name, whether it is a layered picture, its look (`changeLookName`: the image and the states the reference's groups take) and its bake diagnostics, with no file URI, since a served bake's source names none. The language server maps each entry to its artwork files with the compiled program that ran (`morphArtworkFiles`), so a layered picture's diagnostics land on their own files, and ignores an image that program does not hold. A change reference carries the source token its key is built from (`MorphRef.source`, from `morphSourceToken`: the served `src` with its file signature, a hash of inline data, or a hash of a layered picture's composition and files), each entry repeats it, and the server keeps an entry only while it equals the token of the artwork the compiled program holds, so a report of a bake from artwork that has since changed shows nothing. An entry without a token shows nothing either. `morphEditorDiagnostics` (`diagnostics.ts`) gives them the `morph-<code>` form and grouping it gives the compiled references. They show while the program that ran is the one compiled and no watched file has changed since. Each problem shows once per artwork, naming every variant it affects. A drawing pair that fails in one segment and again in the segment that moves it back is one problem. Declaration problems stay on the morph block, where compilation puts them. Intentional one-sided art, `blend = cut` flipbooks with no pairs, and a closed-eye aperture of zero area are not reported. A source whose `partner` labels a pose next to it does not draw is reported once per artwork as `partner-missing`, naming the variants, and a drawing `spread` that does not apply as `spread-ignored`. A moved label that draws part of a clip, or that something outside it draws again by reference, is `motion-ignored`.

## Limits

- A pairing unit is one drawn element. Art that splits one shape across several elements with different paint pairs element by element.
- A morph's parent that the scripts do not write, one supplied by definitions, is checked by the same validator as a written field. Its values are merged under the child by the compiler's inheritance, and each issue about a value the child did not write lands on the child's `as`. Checks made while reading the written text itself have no counterpart for such a parent. Two keyframes it lists at the same offset are not reported, though a written `from` beside `0%` is (`Duplicate keyframe position`).
- Text, images and `<use>` instances inside state layers fade or cut; they have no geometry to morph or scale.
- A shape whose geometry the bake cannot read exactly (a length in a unit other than `px`, such as a percentage of the viewport, a length padded with whitespace CSS does not skip, such as a no-break space, or an inline style setting a geometry property such as `r` or `d`) has no geometry either: it fades or cuts with an `unsupported-element` warning, and its parts keep it as authored.
- A reference to drawn art (a `<use>`, or a clip path, mask or pattern that uses it, from a part's own drawings or the groups kept around them) keeps the variant static, with an `unsupported-element` diagnostic, when the morph would split the referenced art between the referencing part and another, or when the referenced art is a state layer or clip target in another part, where the copy could not follow it, or when it holds a drawing that moves on a carrier (a basic shape, or a drawing several tracks draw on), which is hidden while the reference still names it. Unchanging art is copied whole, even when a compositing group keeps it in a live part. The check counts what a copied resource's original ancestors reference even where the resource overrides that property, so it errs towards the static render, never towards a copy that stands still.
- Artwork carrying a style sheet keeps its static render, whatever its rules say; inline `style` attributes and presentation attributes are the styling a morph can play.
- Artwork with an inline style outside the bake's grammar keeps its static render, with one `unsupported-element` error naming the element, its layer and the declaration. Outside the grammar is non-ASCII text or other whitespace, a character reference, a comment, an escape, a string, a brace or bracket block, a parenthesis left open or holding a semicolon, an `all` declaration, a `var()`, `env()` or `attr()` value, a `!` other than one trailing `!important`, a `display` value other than `none` and the single keywords every browser draws an SVG element with (`inline`, `block`, `flex`, `grid`, the table keywords and their kin; not `contents`, which hides most SVG elements), an empty or CSS-wide value (`inherit`, `initial`, `unset`, `revert`, `revert-layer`) of a compositing property, and an opacity, inline or as an attribute, that is not a number or a percentage. A browser drops a value it does not accept and keeps the declaration before it, so a value the bake cannot vouch for could hide that one from it. The static render keeps every attribute as written, trimmed of XML whitespace only, so padding such as a no-break space reads in it as it does in the artwork. Each can change which drawings show, what composites or what moves in a way a plain reading misses; reading less than a browser does is safe, reading something differently is not. Paint keeps its own grammar inside this one.
- A `transform-origin` attribute, or an inline style setting `transform`, `translate`, `rotate`, `scale`, `transform-origin`, `transform-box` or an `offset-*` property, moves a drawing in a way the bake does not follow: the drawing fades instead of moving, and a clip target under it disables the morph, each with an `unsupported-transform` diagnostic. Only `transform` attributes are mapped.
- Artwork with a `transform` attribute outside the transform-list grammar (`affine.ts`) keeps its static render, with one `unsupported-transform` error naming the element, its layer and the attribute. The grammar is the six transform functions (`matrix`, `translate`, `scale`, `rotate`, `skewX`, `skewY`) with their argument counts and plain numbers that fit a double, the arguments and the functions each separated by XML whitespace (space, tab, line breaks) or one comma, with XML whitespace around the list. Outside it are a no-break space or other non-XML whitespace, a unit such as `5px`, a stray token, an empty or doubled separator, functions written with nothing between them and a list whose matrix overflows. A browser drops most of these or reads them differently, so a drawing the bake moved by one would not move where the artwork shows it. A few it draws as written, such as functions with nothing between them (`translate(5)scale(2)`); the grammar declines those too, since reading less than a browser does is safe.
- Drawings and clip targets inside a nested `<svg>` viewport are not mapped; a drawing there fades instead of moving, and a clip target there disables the morph, each with a diagnostic.
- A picture reaches the screen only as pixels on a canvas. The markup of a pose that moves labels is staged in the page while the browser moves it, with its scripts, embedded documents, event handler attributes and `javascript:` links dropped first (`movedMarkup`); other external references in the art load as they would in an SVG image.
