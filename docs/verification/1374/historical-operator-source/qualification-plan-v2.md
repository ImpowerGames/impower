## Bounded-close amendment

The exact production `run` function now races the child close event against its step deadline and a census-failure cancellation. A cancellation gets at most 30 seconds of ownership-checked recovery and one second of close-event grace, then throws into outer supported-driver cleanup. Exit and close remain separately recorded facts; a deadline, kill request, or grace expiration is never called an exit. A root not observed by identity is never signalled. Recovery that exceeds its cap loses permission to issue any later signal after a census returns.

Cleanup commands bypass the 30-second recovery stage, retaining their 15-second command bound plus one-second close grace. This allows all four supported driver-down commands to be attempted before the shared final identity-checked recovery. The overall 14-minute cap remains a final uncertainty boundary, not a clean-release claim. A failed census permanently prevents release from being marked complete because it leaves an ownership observation gap. Any child lacking either an actual exit or a close receipt also prevents release.

## Qualification source to prepare after plan agreement

Use a private Node harness, outside both candidate source trees. Load and SHA-check the frozen guard source, extract the exact `run`, `onCensusFailure`, and `killVerified` declarations by fixed source boundaries, and evaluate them in a VM context with injected finite census/clock/report adapters. Do not copy the implementation into a separately maintained helper. Retain the exact extracted source and its hashes in the qualification receipt. Child commands are finite, private Node fixtures, never application drivers. The fixture owns only its own process and naturally exits within two seconds even if signalling is suppressed. No real taskkill is used in fault-injection cases; record and assert signal requests through an adapter.

Run sequential cases: (1) normal child exit and close, preserving separate actual receipts; (2) child exceeds its short step deadline, verified ownership authorizes only that exact identity, and cleanup sentinel executes; (3) child naturally exits but its close notification is withheld by the event adapter, proving the close grace reaches cleanup and leaves release uncertain; (4) root identity is never observed, proving no signal and cleanup still executes; (5) census rejects while the finite child is alive, proving active cancellation reaches cleanup rather than leaving the spawn promise pending; (6) injected recovery scan exceeds its bound, proving a late scan cannot issue a signal after the recovery lease closes; (7) supported-down-mode timeout, proving no 30-second recovery delay is inserted before the next cleanup sentinel; (8) current census contains a foreign or reused PID identity, proving no signal is issued to it. Wait for every real fixture process's actual exit and close before releasing the qualification slot, independently of what the injected observer exposes to `run`.

Use scaled timers only for the synthetic long-recovery case, with a recorded scale mapping. Keep at least one real one-second close grace at the unchanged production duration. Cap each case at five seconds and the entire qualification harness at 60 seconds. On any failure, stop subsequent cases, preserve logs, and report the actual fixture process census; do not retry or claim application verification.

For the periodic helper recorder, extract and hash the exact added host-side recorder block from the frozen helper and execute it with temporary output paths and host arrays. Allow at least two real one-second ticks, change the host arrays between ticks, then run its exact final clear/flush path. Assert the JSONL snapshots preserve the observed sequence, the report holds the final host buffer, the timer stops, and a deliberate write failure preserves the earlier primary failure while recording the capture failure. This proves only host-side persistence. It does not prove recovery of unread browser events, application behavior, visual correctness, or process ownership.

Retain raw stdout/stderr, JSON receipts, fixture actual exit/close timestamps, timer-scale records, source hashes, and a final empty owned-process census.
